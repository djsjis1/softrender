# 05 · 深度测试与剔除

> 三角形按数组顺序画，后画的盖住先画的——这与远近无关，于是 `stage3` 的实心立方体才会"穿帮"。本篇用两个机制解决遮挡与浪费：**深度缓冲（Z-buffer）** 让每个像素只留最近的片元；**背面剔除** 直接丢掉永远看不见的背面三角形。

## 一、问题：谁该盖住谁

当两个物体在屏幕上重叠，重叠区域的像素应该显示**离相机更近**的那个。但光栅化是"来一个三角形画一个"，绘制顺序由数组决定，和远近毫无关系。

最古老的解法是**画家算法**：把三角形按深度从远到近排序，像画家先画远景再画近景那样覆盖。但它有两个致命缺陷：

1. **互相穿插的物体排不出全序**。A 一部分在 B 前、一部分在 B 后，怎么排都错。`stage3` 左半屏的穿帮就是这类问题。
2. **每帧排序昂贵**，且动态场景排序不稳定。

我们需要一个**与绘制顺序无关**、**逐像素**判断远近的方法。这就是 Z-buffer。

## 二、Z-buffer 算法

思想朴素而强大：除了颜色缓冲，再开一块同尺寸的**深度缓冲**，每个像素记录"目前画到这里的最近片元的深度"。每画一个片元，拿它的深度和缓冲里的比：

- 若**更近**：覆盖颜色，并更新深度缓冲。
- 若**更远或相等**：丢弃，什么都不做。

```
初始化 depth[所有像素] = +∞
对每个片元 (x, y, z):
    if z < depth[y][x]:
        depth[y][x] = z
        color[y][x] = 片元颜色
```

代码见 `include/softrenderer/core/depthbuffer.h` 的 `testAndSet`，正是这个"比较—更新—返回是否通过"的原子操作。

**为什么它与顺序无关？** 因为无论先画近的还是先画的远的，最终每个像素留下的都是所有竞争者里的最小深度。穿插问题也随之消失——穿插处每个像素各自独立比深度，谁近谁赢，不需要全局排序。`stage4` 里球与立方体穿插的那条交线，正是逐像素判断的明证。

代价是**多一块内存**（每像素一个浮点）和**每片元一次比较**。但相比画家算法的排序与穿插失败，这代价太划算了——Z-buffer 是实时渲染能成立的支柱之一。

## 三、深度从哪来：插值

每个片元的深度 $z$ 不是凭空来的。顶点经视口变换后已带 $z\in[0,1]$，三角形内部用**重心坐标线性插值**：

$$z(p) = \alpha\, z_0 + \beta\, z_1 + \gamma\, z_2$$

这里有个微妙之处：**NDC 的 $z$ 在屏幕空间是线性的**，所以可以直接重心插值；但纹理坐标 $u,v$ 在屏幕空间**不**线性（`06` 会讲透视校正）。深度恰好属于"可以直接插"的那一类，省心。

## 四、背面剔除：免费省一半

一个封闭物体（立方体、球），从外面看，**背对你的那一半面永远被前面那一半挡住**。既然永远看不见，何必光栅化它们？

判断方法极便宜：看三角形在**屏幕空间**的绕序。约定正面是逆时针，那么把屏幕坐标代入 2D 叉积（边函数）算有向面积：

$$\text{area2} = (p_1 - p_0) \times (p_2 - p_0)$$

- 正 → 逆时针 → 正面 → 画。
- 负或零 → 顺时针/退化 → 背面 → 丢。

代码在 `renderer.h` 里：`if (cullBackface && area2 <= 0) return;`。一次叉积，丢掉约一半三角形，光栅化和片元着色的工作量直接减半，**且不改变画面**（因为背面反正被挡住）。这是性价比最高的优化。

> 何时要关背面剔除？渲染**单面片**时——比如一片只有正面的地面、植被 billboard、或半透明物体。我们的地面平面就关了剔除（`cullBackface = false`），否则从某些角度它会被当成背面丢掉。`stage6` 里用 `obj.texture == &checker` 来识别地面并关剔除。

## 五、透视深度非线性与 Z-fighting

`04` 提到，透视投影的 $z$ 映射**不是线性**的：深度值被往远端挤压。直观后果是——**近处深度精度高，远处精度低**。同样 1 米的距离差，在近处对应很大的 $z$ 差，在远处对应几乎为 0 的 $z$ 差。

这带来两个实践要点：

1. **近平面别设太近**。`nearZ` 越小，精度分布越极端，远处越容易出问题。在满足构图的前提下，把 `nearZ` 尽量设大（比如 0.1 而非 0.001）。
2. **Z-fighting**：当两个面几乎共面（如贴花贴在墙上），它们的深度差小于远处那点可怜的精度，比较结果在像素间随机跳变，画面出现"闪烁的斑纹"。缓解办法：拉开两面的距离、用深度偏移（depth bias）、或避免共面。

> 动手验证非线性：`stage06_depth` 输出的深度可视化图 `stage06_depth_zbuf.tga`，代码里专门做了"扫描实际 [min,max] 再线性拉伸"。如果你改成直接用 `1 - z`，会发现**几乎全黑**——因为透视深度全挤在接近 1 的远端，`1-z` 趋近 0。这张全黑图，就是"透视深度非线性"最直观的证据。

## 六、深度缓冲可视化

把深度缓冲本身当图像看，是调试遮挡的利器：近处映射成亮、远处映射成暗。`stage06_depth.cpp` 末尾就是这么做的。一张好的深度图，应该像一张"灰度浮雕"——物体的前后层次一目了然，球心最亮、边缘渐暗。若深度图出现不该有的亮斑或断层，往往是深度写错或裁剪有问题的信号。

## 八、动手实验

1. **关深度测试**：在 `renderer.h` 里把 `if (!zbuf_.testAndSet(...)) continue;` 注释掉，运行 `stage08_shader`，画面退回 `stage05` 那种穿插穿帮。体会 Z-buffer 的作用。
2. **关背面剔除**：设 `renderer.cullBackface = false`，看立方体"内外都画"，背面把正面盖花。理解剔除在遮挡正确时的"无害省功"。
3. **制造 Z-fighting**：放两个完全共面的三角形（同位置同朝向），看交界处闪烁。再把其中一个沿法线挪 0.001，闪烁消失。体会共面与精度的关系。
4. **看深度非线性**：如第五节所述，把深度可视化改成 `1-z` 直接映射，观察全黑现象。

## 九、小结

- 画家算法排不了穿插、要排序；**Z-buffer** 用一块深度缓冲逐像素留最近者，与顺序无关，是遮挡的正解。
- 深度由顶点 $z$ 经**重心坐标线性插值**得到（NDC 深度在屏幕空间线性）。
- **背面剔除**用屏幕空间 2D 叉积判绕序，免费省约一半三角形；单面片需关闭。
- 透视深度**非线性**：近精远粗。`nearZ` 别太小；共面会 Z-fighting。
- 深度缓冲可视化是调试遮挡的利器。

遮挡解决了，画面却还是"纯色面片"。下一篇给表面贴上图案——**纹理映射**，并揭开一个隐藏陷阱：透视校正插值。
