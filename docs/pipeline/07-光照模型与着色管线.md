# 07 · 光照模型与着色管线

> 有了纹理，表面还是"平"的——没有明暗，看不出立体。光照模型回答"给定法线、光方向、视线方向，这个点该多亮、什么颜色"。而**着色管线**回答"这套光照计算，放在流水线的哪个阶段、对每个顶点还是每个像素做"。本篇把两者一起讲清，并引出本项目最重要的架构抽象：可编程着色器。

## 一、经验光照模型：Blinn-Phong

真实光传输极其复杂（全局光照、多次反弹……）。实时渲染早期用**经验模型**近似：不模拟物理，只凑出"看起来对"的明暗。最经典的是 Phong 家族，把光照拆成三项相加：

$$L = \underbrace{k_a \cdot I_a}_{\text{环境}} + \underbrace{k_d \cdot I_l \cdot \max(0, N\cdot L)}_{\text{漫反射}} + \underbrace{k_s \cdot I_l \cdot \max(0, N\cdot H)^{s}}_{\text{高光}}$$

逐项解释（代码见 `src/shader/shaders.h` 的 `blinnPhong`）：

- **环境项** $k_a I_a$：一个常数底色，模拟"间接光"——即使背对光源，物体也不全黑。物理上不准，但没有它画面会死黑。
- **漫反射项**：`02` 讲过的 $N\cdot L$。表面正对光则亮，侧对则暗，与视线无关——这是"哑光"材质的明暗来源，塑造体积感。$k_d$ 是材质基色（或纹理颜色，即 albedo）。
- **高光项**：模拟光滑表面的"亮点"。$(N\cdot H)^s$ 中 $s$ 是**高光指数（shininess）**，越大亮点越小越锐（像金属/塑料），越小越糊（像皮肤）。

### 半程向量 H：Blinn 的改进

原始 Phong 高光用反射向量 $R$ 与视线 $V$ 的点积 $(R\cdot V)^s$。Blinn 改用**半程向量** $H = \text{normalize}(L + V)$，即光方向与视线方向的角平分线，高光项变成 $(N\cdot H)^s$。

为什么更好？(1) 算 $H$ 比算反射向量 $R$ 便宜；(2) 当表面几乎平行于光线时，Phong 的 $R\cdot V$ 会突然截断产生瑕疵，Blinn 的 $N\cdot H$ 更平滑。现代实时渲染几乎都用 Blinn-Phong。代码里 `Hh = (L + V).normalized()` 正是它。

> 注意高光只在 $N\cdot L>0$（朝向光的一面）才计算，否则背光面会冒出鬼影亮点。代码用 `if (diff > 0)` 守卫。

## 二、可编程着色管线：我们的架构抽象

光照公式写好了，但**对谁算、在哪算**？这正是 GPU "可编程着色器"要解决的，而我们在 `src/shader/shader.h` 用 C++ 抽象类复刻了同一套思想。

### Shader 基类 = 一对可编程函数

```cpp
struct Shader {
    // ... 一堆 uniform（见下）...
    virtual Vec4f vertex(const Vertex& in, Varyings& out) = 0;   // 顶点着色器
    virtual bool  fragment(const Varyings& v, Vec3f& color) = 0; // 片元着色器
};
```

- `vertex` 对**每个顶点**执行：把模型坐标变换到裁剪空间（返回 `mvp * position`），并把需要在三角形内插值的量写进 `out`（一个 `Varyings`）。
- `fragment` 对**每个像素**执行：拿到插值后的 `Varyings`，算出该像素颜色；返回 `false` 表示丢弃该片元（GLSL 的 `discard`）。

具体着色器（Flat/Gouraud/Phong）继承它，各自实现这两个函数——**光照算在顶点还是片元，就由这两个函数怎么写决定**。这和写 GLSL 的两个 shader 函数是一回事。

### Varyings 与 uniform：两类数据

- **Varyings**（`struct Varyings`）：顶点着色器的输出、片元着色器的输入，光栅化器负责在三角形内做**透视校正插值**（`interpolateVaryings`，见 `06`）。对应 GLSL 的 `out`/`in` 插值变量。里面装着世界坐标、法线、UV、切线、顶点色等。
- **uniform**：`Shader` 的成员变量（`model`、`lightDir`、`cameraPos`、`baseColor`、`texture`……），整帧对所有顶点/片元**只读且相同**，渲染前由外部设置。对应 GLSL 的 `uniform`。

记住这套对应（`01` 也给过对照表），你看任何图形 API 的着色器代码都能秒懂。

## 三、三种着色策略：光照放在哪一阶段

同一套 Blinn-Phong，按"在管线哪里算"分成三种，效果与开销递进。这是本篇最该建立直觉的地方，`stage6` 的三张对比图（`output/stage6_flat/gouraud/phong.tga`）一目了然。

### Flat 着色：逐三角形

用三顶点世界坐标叉积算**一个面法线**，对整个三角形只算一次光照，整面同色。代码 `FlatShader::geometry` 在逐三角形钩子里算好颜色，`fragment` 直接返回。

- 效果：能清楚看到**每个三角形的棱面**（球变成多面体）。
- 开销：最省。
- 适用：低多边形风格、或本就硬边的物体。

### Gouraud 着色：逐顶点

在 `vertex` 里对**每个顶点**算一次光照，把结果颜色写进 `Varyings::color`，交给光栅化器**插值颜色**。`fragment` 直接用插值后的颜色。

- 效果：平滑，但**高光会糊**——若高光落在三角形内部而非顶点，顶点处都没采到亮点，插值出来就是一片平庸的亮斑，甚至丢失。球面上的高光会显得"胖而软"。
- 开销：中等。
- 历史地位：早期硬件的主流，今天多被 Phong 取代。

### Phong 着色：逐片元

`vertex` 只插值**法线**（和位置、UV），`fragment` 里对**每个像素**重新算完整光照。

- 效果：高光**锐利正确**，明暗过渡最细腻。
- 开销：最贵（每像素一次光照）。
- 关键细节：法线插值后长度不再是 1，**必须重新 `normalized()`** 才能点积，否则亮度错。代码 `PhongShader::fragment` 里 `blinnPhong` 第一行就做了归一化。

> 一句话区分：**Flat 插颜色（一个面一个值）、Gouraud 插颜色（逐顶点值）、Phong 插法线（逐像素算光）。** 插值的东西越"原始"，结果越准，开销越大。

## 四、法线变换：别忘逆转置

光照在世界空间算，法线也得送到世界空间。`02` 讲过：法线要用**逆转置矩阵** $(M^{-1})^T$ 变换，而非模型矩阵本身，否则非等比缩放下法线歪斜、光照错乱。

代码里 `Shader::normalMatrix` 存这个矩阵，`toWorldNormal` 用它把模型法线送进世界空间并归一化。`stage6` 主循环每帧设 `sh->normalMatrix = model.inversed().transposed();`。当模型只含旋转+等比缩放时可偷懒用旋转部分，但通用写法就是逆转置。

## 六、动手实验

1. **三图对比**：打开 `stage6_flat/gouraud/phong` 三张图，盯球体的高光。Flat 是棱面块、Gouraud 高光发糊、Phong 高光锐利。把这份视觉差异和"插值什么"对上。
2. **调 shininess**：在 `stage6_offline` 里把 `shininess` 从 32 改到 4（高光变大变糊）和 256（变成针尖亮点）。理解指数控制高光"硬度"。
3. **关漫反射看高光**：在 `blinnPhong` 里临时把 `diff` 强制为 0，只剩环境+高光，球会变成"黑底上一个亮点"——看清高光项的独立形状。
4. **验证法线归一化**：在 `PhongShader::fragment` 里把 `blinnPhong` 内对 `N` 的 `normalized()` 去掉，并故意给球一个非等比缩放模型矩阵，看光照歪掉。体会插值后归一化的必要。

## 七、小结

- 经验光照 = 环境 + 漫反射（$N\cdot L$）+ 高光；**Blinn-Phong** 用半程向量 $H$ 算高光，便宜且稳。
- **可编程管线**抽象成 `vertex`/`fragment` 两个函数 + `Varyings`（插值）+ uniform（只读），与 GPU 着色器一一对应。
- 三种着色策略：**Flat** 逐面、**Gouraud** 逐顶点插颜色、**Phong** 逐片元插法线；精度与开销递增，高光表现差异显著。
- 法线送进世界空间要用**逆转置矩阵**，插值后还要**重新归一化**。

光照让画面立体了，但当相机贴近物体时，跨近平面的三角形会整块消失。下一篇用**裁剪**彻底解决它。
