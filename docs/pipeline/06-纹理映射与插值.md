# 06 · 纹理映射与插值

> 纯色面片太单调。纹理映射（texture mapping）把一张 2D 图像"贴"到 3D 表面，是画面丰富度的主要来源。但贴图藏着一个著名陷阱：在屏幕空间直接插值纹理坐标会**扭曲**。本篇讲清纹理怎么采样，以及为什么必须做**透视校正插值**——`stage5` 那张左右对比图，就是为它而生。

## 一、纹理与 UV 坐标

纹理就是一张图像，由**纹素（texel）** 组成。要把它贴到三角形上，需要告诉每个顶点"我对应纹理上的哪个位置"，这就是 **UV 坐标** $(u, v)$，通常归一化到 $[0,1]$：$u$ 向右、$v$ 向上，$(0,0)$ 在左下角（与本项目的图像存储约定一致，见 `include/softrenderer/resource/texture.h`）。

光栅化时，三角形内部的每个像素用重心坐标插值出它的 $(u,v)$，再去纹理里查颜色。整个流程：

```
顶点带 uv ──插值──▶ 片元的 (u,v) ──采样──▶ 纹理颜色 ──▶ 片元颜色
```

注意"插值"和"采样"是两步：插值在屏幕空间给出连续的 $(u,v)$，采样把连续坐标变成离散纹素的颜色。

## 二、采样：从连续坐标到纹素颜色

$(u,v)$ 一般不落在纹素中心，怎么取颜色？两种基本方法：

**最近邻（nearest）**：四舍五入到最近的纹素。

```cpp
int x = int(u * width);   // 取整 = 最近邻
```

快，但放大时呈**马赛克方块**——复古像素风由此而来。

**双线性（bilinear）**：取包围 $(u,v)$ 的 4 个纹素，按小数距离做两次线性插值。设采样点落在纹素 $(x_0,y_0)$ 右下方 $(t_x, t_y)$ 处：

$$c = \text{lerp}_y(\text{lerp}_x(c_{00}, c_{10}, t_x),\ \text{lerp}_x(c_{01}, c_{11}, t_x),\ t_y)$$

代码 `Texture::sampleBilinear` 正是如此，并先减 0.5 让整数坐标对齐纹素中心。放大时**平滑**，是主流做法。

> 双线性仍会在**缩小**时出问题：当一个像素覆盖很多纹素（远处地面），只采 4 个会漏掉中间的，产生闪烁摩尔纹。完整解法是 **mipmap**——预存逐级缩小的纹理链，按像素覆盖的纹素数选合适层级采样。本项目为简洁未实现 mipmap，但你要知道远处纹理发闪的根源与此。

**环绕方式**：当 $(u,v)$ 超出 $[0,1]$（比如 UV 重复平铺的棋盘地面），怎么办？本项目用 **Repeat**：取小数部分循环，代码 `wrap` 用取模实现，负数也正确回绕。其他方式还有 Clamp（夹到边缘）、Mirror（镜像重复）。

## 三、透视校正插值：本篇的核心

现在到了著名陷阱。直觉上，$(u,v)$ 和颜色、深度一样，用重心坐标在屏幕空间线性插值不就行了？**不行。** 在屏幕空间直接线性插值 UV，画面会**沿三角形对角线折断、扭曲**——`stage5` 左半屏那惨不忍睹的棋盘就是证据。这正是早期 PS1 游戏纹理抖动的根源。

### 为什么屏幕空间线性插 UV 是错的

回顾 `04`：屏幕坐标是**透视除法之后**的结果，即 $x_s = x/w$ 这种形式。透视除法是个**非线性**操作（除以 $w$）。一个在 3D 空间里线性变化的量（如纹理坐标 $u$ 沿一条 3D 直线均匀变化），经过"除以 $w$"后，在屏幕空间**不再线性**——近处 $w$ 小、变化被放大，远处 $w$ 大、变化被压缩。

所以直接在屏幕像素间线性插 $u$，等于用错了插值空间，近处纹理被拉伸、远处被挤压，三角形越大、越斜，扭曲越明显。

### 正确做法：插 u/w、v/w、1/w

数学上可以证明：**$u/w$、$v/w$ 和 $1/w$ 这三个量，在屏幕空间是线性的。** 于是正确流程是：

1. 用重心坐标线性插值这三个量：
$$(u/w)' = \alpha\, u_0/w_0 + \beta\, u_1/w_1 + \gamma\, u_2/w_2$$
$$(1/w)' = \alpha\, 1/w_0 + \beta\, 1/w_1 + \gamma\, 1/w_2$$
2. 两者相除，还原真正的 $u$：
$$u = \frac{(u/w)'}{(1/w)'}$$

$v$ 同理。这就是**透视校正插值**。代码 `shader.h` 的 `interpolateVaryings` 对每个属性都这么做：先乘 $1/w_i$ 加权，求和后再除以 $\sum bc_i/w_i$。GPU 里 varying 的默认插值方式也正是它。

### 直觉理解

可以这样记：**屏幕空间只对"已经除过 $w$ 的东西"线性。** 所以想插任何 3D 属性 $a$，都要先把它"乘回 $w$ 的世界"——插 $a/w$ 和 $1/w$，最后再除回来。深度 $z$ 是个例外：NDC 的 $z$ 经过投影矩阵的特殊构造，恰好能在屏幕空间线性插（`05`），所以深度不用校正。

> 一句话：**透视除法破坏了线性，透视校正用 $1/w$ 把它补回来。**

## 五、动手实验

1. **看扭曲**：运行 `stage5`，盯左半屏的棋盘——注意它沿每个三角形的对角线"折"了一下，格子变成平行四边形而非正方形。这就是仿射插值的罪证。
2. **换最近邻**：在 `stage5` 里把 `sampleBilinear` 换成 `sampleNearest`，看棋盘边缘出现锯齿马赛克。体会两种采样的视觉差异。
3. **改 UV 重复次数**：`meshgen::plane(20, 12)` 的第二个参数是 UV 重复次数，改成 2 看棋盘变稀疏、改成 40 看变密且远处更闪（mipmap 缺失的摩尔纹）。
4. **关掉校正看极端情况**：相机正对地面（不倾斜）时，仿射和校正差异很小；越倾斜、越接近地平线，差异越大。理解"扭曲程度取决于透视强度"。

## 六、小结

- 纹理映射 = 顶点带 UV → 插值得片元 UV → 采样得颜色。
- **最近邻**快而有马赛克；**双线性**平滑，是主流；缩小闪烁需 **mipmap**（本项目未实现）。
- UV 超出范围靠**环绕方式**处理，本项目用 Repeat。
- **屏幕空间线性插 UV 是错的**，因为透视除法非线性。
- **透视校正**：插 $u/w, v/w, 1/w$ 再相除，补回被透视破坏的线性。深度是例外，可直接插。
