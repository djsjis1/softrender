# 16 · 完整 6 面视锥裁剪

> 只裁近平面不够——物体从左右上下远五个面穿出视锥时，NDC 坐标超出 [-1,1]，光栅化包围盒覆盖整屏。完整 6 面裁剪保证只有视锥内的几何进入光栅化。

## 一、问题

近平面裁剪解决了除零崩溃（w ≤ 0）。但物体会从其他五个面"漏"出去：

- **左右**：物体在屏幕外但仍在光栅化，包围盒覆盖全宽
- **上下**：同理
- **远平面**：远处物体被近平面裁剪切掉了身后部分，但远端的三角形仍可能伸到无限远

每漏一个面 = 更多无用三角形被光栅化 = 性能浪费。6 面全部裁干净，只留视锥内的几何。

## 二、6 个平面方程（裁剪空间）

裁剪空间中，视锥的 6 个面的内侧判据统一为 `d >= 0`：

| 平面 | 距离函数 `d` | 说明 |
|---|---|---|
| Near | `w + z` | 最近可看 |
| Far | `w - z` | 最远可看 |
| Left | `w + x` | 视锥左边界 |
| Right | `w - x` | 视锥右边界 |
| Bottom | `w + y` | 视锥下边界 |
| Top | `w - y` | 视锥上边界 |

所有平面方程都在个位数内——判断一个顶点在不在视锥内，一次加减即可。这就是为什么裁剪在裁剪空间做最便宜。

## 三、Sutherland-Hodgman 迭代

对三角形逐平面裁剪。每裁一个面，多边形顶点数可能 +1。三角形经 6 面后最多可能产生 9 个顶点（极端情况），实际很少超过 6。

```cpp
// clip.h
ClipVertex poly[12];  // 输入 3 顶点，输出最多 ~9 顶点
int n = clipTriangleFullFrustum(tri, poly);
// n = 0: 全在外面，丢弃
// n >= 3: 三角扇拆分 (poly[0], poly[1], poly[2]), (poly[0], poly[2], poly[3])...
```

用双缓冲 `bufA/bufB` 交替，避免动态分配。

## 四、代码入口

| 操作 | 代码位置 |
|---|---|
| 6 面距离函数 | `raster/clip.h`: `clipPlaneDist()` |
| 单面裁剪 | `clipPolygonOnePlane()` |
| 完整 6 面裁剪 | `clipTriangleFullFrustum()` |
| Renderer 调用 | `renderer.h`: `nearClip=true` 分支 |

## 五、动手实验

1. **FOV 极小**：把 `fovY` 设成 5°，让物体大部分在视锥外——观察裁剪正确切掉超出部分。
2. **注释 Far/Left/Right/Top/Bottom**：在 `clipTriangleFullFrustum` 循环里只保留 near，看物体从侧面"泄漏"到屏幕外产生巨量无效光栅化。
3. **打印 n**：在裁剪后打印输出顶点数，观察三角形被切成 3/4/5/6 个顶点的频率。

## 六、为什么在裁剪空间裁（而非 NDC）

| 空间 | 除法前/后 | 平面方程复杂度 | 属性插值 |
|---|---|---|---|
| **Clip**（裁剪空间） | 除法前 | 极简（`w±x` 等） | 普通线性（对） |
| NDC | 除法后 | 复杂 | 需透视校正（错） |

在裁剪空间裁有三大优势：`w` 还完好（不会除零）、方程极简、属性线性直插不讲矫。这也是 GPU 选裁剪空间的原因。
