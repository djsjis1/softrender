# 08 · 裁剪：齐次空间的 Sutherland-Hodgman

> 当相机贴近地面或一堵墙，会有三角形**横跨近平面**——一部分在相机前、一部分在相机后。前几阶段我们用"任一顶点在相机后就丢弃整个三角形"来兜底，代价是地面出现大片空洞。本篇用**裁剪**彻底解决：在透视除法之前，把跨边界的三角形沿近平面切开，只保留可见部分。

## 一、为什么必须裁剪：w ≤ 0 的灾难

回顾 `04`：透视除法要算 $x/w, y/w, z/w$，而 $w = -z_{view}$。当顶点在相机**后方**或正好在相机平面上，$z_{view} \ge 0$，于是 $w \le 0$。这会导致：

- $w = 0$：**除零**，坐标变无穷大或 NaN，光栅化直接崩。
- $w < 0$：除法把坐标**翻转**到屏幕的另一边，一个本该在身后的顶点被画到面前，三角形拉伸成横跨整屏的怪物。

所以**绝不能在 $w\le 0$ 的顶点上做透视除法**。必须在除法之前，把这些"危险顶点"处理掉。

### 粗暴剔除的代价

最简单的处理是：只要三角形有一个顶点 $w\le 0$，就**整块丢弃**。这正是 `stage5`/`stage6` 早期的做法。它不会崩，但会**错**——一个明明大部分在相机前的大三角形，仅因一个角伸到身后，就整块消失，于是贴近相机的地面、墙面出现**空洞**（`stage7` 左半屏的棕色破洞就是它）。

我们需要的是"切掉身后那一小块，保留身前的大部分"，而非"连坐"。这就是裁剪。

## 二、为什么在裁剪空间裁

裁剪可以放在多个空间，但**裁剪空间**（透视除法之前、投影矩阵之后）是最佳选择，原因有三：

1. **除法还没发生**，$w$ 还完好，没有除零/翻转问题，正是要规避的源头。
2. 视锥的六个面在裁剪空间里是**简单的平面方程**，判断"在内在外"极其便宜。
3. 此时坐标与所有顶点属性**都还是线性的**，求交点时直接线性插值即正确——不需要 `06` 的透视校正（校正是除法之后才需要的）。

## 三、近平面方程：z + w ≥ 0

裁剪空间里，NDC 的可见范围是 $z_n \in [-1, 1]$，其中 $z_n = z_c / w_c$。近平面对应 $z_n = -1$，即：

$$\frac{z_c}{w_c} = -1 \quad\Rightarrow\quad z_c = -w_c \quad\Rightarrow\quad z_c + w_c = 0$$

于是**内侧（可见）判据**为：

$$d = z_c + w_c \ge 0$$

一个顶点的 $d = z + w$ 就是它到近平面的"有符号距离"（差一个常数倍）。$d\ge 0$ 在内，$d<0$ 在外。代码 `clip.h` 的 `clipTriangleNearPlane` 开头就是这个 lambda。

> 同理，远平面是 $z_c - w_c \le 0$，左右上下四个面是 $\pm x_c \le w_c$、$\pm y_c \le w_c$。本项目只裁近平面（它最致命，$w\le0$ 的崩溃只来自它），其余五个面靠后面的视口夹取兜底。完整实现可对六个面各跑一遍同一算法。

## 四、Sutherland-Hodgman：沿一个平面切多边形

这是裁剪的经典算法，思想是**逐边扫描，保留内侧、补上交界**。对三角形的三条边 $v_0\!\to\!v_1, v_1\!\to\!v_2, v_2\!\to\!v_0$，依次看每条边的两端点在内还是在外，按四种情况输出：

| 当前点 | 下一点 | 输出 |
|---|---|---|
| 内 | 内 | 当前点 |
| 内 | 外 | 当前点 + 交点 |
| 外 | 内 | 交点 |
| 外 | 外 | （无） |

其中**交点**是边与平面的交点，用 $d$ 线性插值：

$$t = \frac{d_{cur}}{d_{cur} - d_{nxt}}, \qquad P_{hit} = \text{lerp}(cur, nxt, t)$$

遍历完三条边，输出顶点数只可能是 **0**（全在外，丢弃）、**3**（全在内，或切掉一角仍三角）、**4**（切掉一角变成四边形）。代码 `clipTriangleNearPlane` 正是这个循环，返回输出顶点数。

### 四边形怎么画：三角扇

光栅化器只认三角形。裁出的 4 顶点凸多边形，用**三角扇**拆成两个三角形：$(p_0, p_1, p_2)$ 和 $(p_0, p_2, p_3)$。`renderer.h` 里 `for (t = 1; t+1 < n; ++t) rasterTriangle(poly[0], poly[t], poly[t+1])` 就是这步，对 $n=3$ 也通用（循环一次）。

### 交点的属性也要插值

交点是个新顶点，它的位置插值了，**法线、UV、颜色等属性也得按同一个 $t$ 插值**，否则切缝处纹理/光照会跳变。代码 `lerpClipVertex` 对 `pos` 和 `Varyings` 的每个字段一起插值。注意：因为还在裁剪空间（除法前），这里用**普通线性插值**就正确，不需要透视校正。

## 六、动手实验

1. **看空洞**：运行 `stage7`，盯左半屏底部——贴近相机的地面整块消失，露出背景。这就是"连坐式剔除"的代价。
2. **数输出顶点**：在 `clipTriangleNearPlane` 返回前打印 `count`，观察它确实只取 0/3/4。构造一个完全在相机后的三角形，确认返回 0。
3. **关掉裁剪看崩溃边缘**：把 `renderer.h` 裁剪分支临时换成"不裁也不剔除直接除 $w$"，让相机穿过物体，观察画面撕裂甚至 NaN 色斑。理解裁剪是"防崩溃"的护栏。
4. **扩展到远平面**：照近平面的写法，加一个 $d = w - z \ge 0$ 的裁剪 pass，对 `poly` 再裁一次。体会 Sutherland-Hodgman 的"逐平面叠加"特性。

## 七、小结

- $w\le 0$ 会让透视除法除零/翻转，**必须在除法前裁剪**。
- 粗暴"整块剔除"不崩但错，产生空洞；裁剪才是正解。
- 在**裁剪空间**裁：除法前、平面方程简单、属性线性可直插。
- 近平面判据 $z + w \ge 0$；**Sutherland-Hodgman** 逐边保留内侧、补交点，三角形裁成 0/3/4 顶点。
- 4 顶点用**三角扇**拆回三角形；交点的位置与属性按同一参数插值。
- 算法可逐平面叠加，扩展到完整六面视锥裁剪。

裁剪补上了管线的最后一块拼图，相机可以任意贴近物体而不崩不洞。下一篇进入高级特性——**阴影映射与法线贴图**，让画面迈向照片级。
