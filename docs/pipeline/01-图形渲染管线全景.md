# 01 · 图形渲染管线全景

> 在钻进任何细节之前，先站在高空看一遍整条流水线。本篇回答一个问题：**一个 3D 顶点，究竟经过了哪些步骤，才变成屏幕上的一个像素？** 后面每一篇文档，都是这张全景图上某个方框的放大。

## 一、渲染到底在干什么

渲染的输入是三样东西：

1. **几何**：一堆三角形，每个顶点带位置，可能还带法线、纹理坐标、颜色等"属性"。
2. **相机**：从哪里看、朝哪看、视野多宽。
3. **光照与材质**：光从哪来、表面是什么颜色、光滑还是粗糙。

渲染的输出是一张**二维像素图**（帧缓冲）。

中间发生的一切，就是把"三维世界里的三角形"变成"二维屏幕上的彩色像素"。这件事被拆成一条**流水线（pipeline）**，数据像流水线上的工件一样，依次经过若干阶段，每阶段做一件固定的事。GPU 之所以快，很大程度上就是因为这条流水线被硬件并行化了；而我们的软渲染器，则是用 `for` 循环把同一条流水线在 CPU 上老老实实跑一遍。

理解管线的关键，是理解数据在流经它时，所处的**坐标空间**在不断变化。

## 二、五个坐标空间：为什么需要这么多

初学者最大的困惑往往是：为什么不能"一步到位"把模型坐标变成屏幕坐标，而要经过一连串空间？答案是**每个空间只解决一个独立的问题**，把复杂任务分解成可组合的简单步骤。

```
 模型空间        世界空间        相机空间        裁剪空间       NDC          屏幕空间
(model)  ──M──▶ (world)  ──V──▶ (view)  ──P──▶ (clip) ──÷w──▶ (ndc) ──VP──▶ (screen)
 物体自己的      物体在场景       以相机为        准备做        规整的       最终像素
 局部坐标        里的位置         原点观察        透视除法      立方体        坐标
```

逐个解释：

- **模型空间（Model / Object Space）**：顶点在"物体自己"的坐标系里的位置。一个立方体的顶点是 `(-0.5,-0.5,-0.5)..(0.5,0.5,0.5)`，无论它被摆到世界的哪个角落，模型坐标都不变。这样模型数据可以复用。
- **世界空间（World Space）**：所有物体放进同一个全局坐标系后的位置。光照计算通常在这里做，因为光的方向是全局的。模型空间 → 世界空间用**模型矩阵 M**（平移+旋转+缩放）。
- **相机空间 / 视图空间（View / Camera / Eye Space）**：把相机挪到原点、朝向 -Z 后，世界在它眼里的样子。"观察"这件事被转化成了"对世界做一次坐标变换"。世界 → 相机用**视图矩阵 V**（`lookAt`）。
- **裁剪空间（Clip Space）**：乘上**投影矩阵 P** 后的空间。它的妙处在于：透视的"近大远小"还没真正发生，但已经"埋好伏笔"——把距离信息塞进了齐次坐标的 `w` 分量，留给下一步除法。**裁剪**（剔除相机看不到的部分）也在这里做，因为此时判断"在不在视锥内"最简单。
- **NDC（Normalized Device Coordinates，归一化设备坐标）**：做完**透视除法**（坐标除以 `w`）后，所有可见内容被规整进一个标准立方体，三轴都在 `[-1, 1]`。这是个与屏幕分辨率无关的"中转站"。
- **屏幕空间（Screen Space）**：NDC 经**视口变换**映射到具体像素坐标 `(x, y)`，深度 `z` 映射到 `[0, 1]` 留给深度缓冲。到这里，才真正"光栅化"成像素。

> 记忆口诀：**M 把物体摆进世界，V 把世界搬到相机眼前，P 把三维压成裁剪空间，÷w 让透视发生，视口把规整立方体贴到屏幕。**

为什么不在模型空间直接算屏幕坐标？因为那样每加一个物体、每动一下相机，都要重算所有顶点的最终坐标，无法复用。而矩阵链 `P * V * M` 可以**预先乘好**，每个顶点只做一次矩阵乘法。这就是线性代数给图形学的礼物。

## 三、流水线的阶段

坐标空间描述"数据在哪"，流水线阶段描述"对数据做什么"。把两者叠在一起，整条管线长这样：

```
┌─────────────────────────────────────────────────────────────┐
│  1. 顶点处理 (Vertex Processing)                              │
│     每个顶点：乘 MVP，模型空间 → 裁剪空间；同时算出要插值的属性   │
│     对应 GPU 的【顶点着色器】                                  │
├─────────────────────────────────────────────────────────────┤
│  2. 裁剪 (Clipping)                                           │
│     丢掉相机视锥外的部分，跨边界的三角形被切开                   │
├─────────────────────────────────────────────────────────────┤
│  3. 透视除法 + 视口变换                                        │
│     裁剪空间 → NDC → 屏幕坐标                                 │
├─────────────────────────────────────────────────────────────┤
│  4. 背面剔除 (Backface Culling)                               │
│     丢掉背对相机的三角形（约省一半工作量）                       │
├─────────────────────────────────────────────────────────────┤
│  5. 光栅化 (Rasterization)                                    │
│     三角形 → 它覆盖的像素（片元）集合；插值顶点属性到每个片元     │
├─────────────────────────────────────────────────────────────┤
│  6. 片元处理 (Fragment Processing)                            │
│     每个片元：算颜色（光照、纹理采样）                          │
│     对应 GPU 的【片元着色器】                                  │
├─────────────────────────────────────────────────────────────┤
│  7. 深度测试 (Depth Test)                                     │
│     多个片元争抢同一像素时，只留最近的                          │
├─────────────────────────────────────────────────────────────┤
│  8. 写入帧缓冲                                                │
└─────────────────────────────────────────────────────────────┘
```

注意顺序里有个**反直觉**的点：在我们的实现里，深度测试发生在片元着色**之后**的写入环节（先算颜色，再比深度，比赢了才写）。GPU 通常反过来——先比深度，比赢了才跑昂贵的片元着色器（Early-Z 优化）。我们为了代码清晰没做这个优化，但你要知道真实硬件是怎么省的。

## 四、两套术语的对照

这套文档同时使用"软渲染器术语"和"GPU 术语"，因为后者是你将来用图形 API 时会遇到的。先建立对照：

| 概念 | 我们的代码 | GPU / GLSL 术语 |
|---|---|---|
| 每顶点执行的函数 | `Shader::vertex` | 顶点着色器 vertex shader |
| 每像素执行的函数 | `Shader::fragment` | 片元着色器 fragment shader |
| 顶点间插值的量 | `Varyings` | varying / in-out 变量 |
| 整帧统一设置的量 | `Shader` 的成员（model/lightDir…） | uniform |
| 顶点带的数据 | `Vertex` | 顶点属性 attribute / in |
| 像素的候选值 | 片元 fragment | fragment |
| 最终像素数组 | `Framebuffer` | 颜色附件 color attachment |
| 深度数组 | `DepthBuffer` | 深度附件 depth attachment |

记住这张表，后面看到 `Varyings` 就条件反射地想到"哦，这就是 GLSL 里在顶点着色器写、片元着色器读的那个插值变量"。

## 五、坐标系约定（务必记牢）

约定不统一是图形 bug 的头号来源。本项目全程遵守：

- **右手坐标系**：拇指 X、食指 Y、中指 Z，符合右手定则。
- **Y 向上**：世界与屏幕都如此。Framebuffer 的第 0 行在**底部**。
- **相机看向 -Z**：相机空间里，相机前方的物体 z 为负。这是 OpenGL 惯例。
- **NDC 范围**：`x, y, z ∈ [-1, 1]`。
- **屏幕深度**：视口变换后 `z ∈ [0, 1]`，0 是近平面，1 是远平面，**值越小越近**。
- **三角形正面**：从相机看，顶点**逆时针**排列的面是正面；顺时针是背面（被背面剔除丢弃）。
- **像素采样点**：取像素**中心** `(x+0.5, y+0.5)`，而非整数角点。

> 如果你以后看到画面上下颠倒、左右镜像、深度反了、面被剔光了，十有八九是某条约定对不上。回来查这张表。

## 六、对应代码：一条管线的全貌

整条流水线被串在一个函数里：`Renderer::drawMesh`（见 `include/softrenderer/render/pipeline/renderer.h`）。它对一个三角形的处理，正好对应上面 8 个阶段，代码注释也按 1–8 标号：

1. **顶点处理**：`shader.vertex(...)` 返回裁剪空间坐标，填充 `Varyings`。
2. **裁剪**：`clipTriangleNearPlane(...)` 沿近平面切开，可能产出 3 或 4 个顶点。
3. **透视除法 + 视口**：`clip.xyz * (1/clip.w)` 得 NDC，再 `viewport_.transformPoint` 得屏幕坐标。
4. **背面剔除**：屏幕空间有向面积 `cross2(...) <= 0` 则丢弃。
5. **光栅化**：包围盒遍历 + `barycentric` 判断像素是否在三角形内。
6. **片元处理**：`interpolateVaryings` 插值属性，`shader.fragment` 算颜色。
7. **深度测试**：`zbuf_.testAndSet` 比深度。
8. **写入**：`fb.setPixel`。

读 `renderer.h` 时，把每个代码块和上面流水线的方框一一对上，你会发现"原来 GPU 教程里那些抽象阶段，就是这几行循环"。这正是手写渲染器的意义。

## 七、动手实验

1. **打印中间坐标**：在 `stage05_transform.cpp` 里，挑一个顶点，依次打印它在 model、view、clip、NDC、screen 各空间的值。观察：相机空间里它的 z 是不是负的？NDC 是不是落在 `[-1,1]`？这能把抽象空间变成具体数字。
2. **关掉某个阶段看后果**：在 `renderer.h` 里临时把背面剔除 `if (cullBackface && area2 <= 0) return;` 注释掉，运行 `stage08_shader`。你会看到立方体"内外都画"，背面盖住正面——直观理解剔除在干什么。
3. **颠倒深度约定**：把 `DepthBuffer::testAndSet` 里的 `z < slot` 改成 `z > slot`，看画面变成"远处的盖住近处的"。理解"值小=近"这条约定。

## 八、小结

- 渲染 = 把三维三角形变成二维像素，靠一条**流水线**。
- 数据流经 **模型 → 世界 → 相机 → 裁剪 → NDC → 屏幕** 六个空间，每个空间解决一个问题，用矩阵 `M / V / P` 与透视除法 `÷w` 衔接。
- 流水线八大阶段：顶点处理、裁剪、透视除法+视口、背面剔除、光栅化、片元处理、深度测试、写入。
- 我们的 `Renderer::drawMesh` 就是这八阶段的 CPU 直译。
- 牢记坐标系约定，它们是排错的第一依据。

## 九、零基础补充：跟踪一个顶点

光看概念容易懵。这里用**具体数值**跟踪一个顶点走完全程。

假设有一个立方体的顶点 `pos = (1, 0.5, -2)`。

### Step 1: 模型矩阵 → 世界空间

```cpp
Mat4 model = Mat4::translate(0, 0, -5) * Mat4::rotateY(0.2f);
Vec3f world = model.transformPoint(pos);
// 结果大概是: (0.98, 0.5, -6.8) —— 被转了一点、移到了 z=-5 附近
```

### Step 2: 视图矩阵 → 相机空间

```cpp
Mat4 view = lookAt({0, 0, 3}, {0, 0, 0}, {0, 1, 0});
Vec3f camera = view.transformPoint(world);
// 相机在 (0,0,3) 看向原点。顶点现在在相机坐标系：
// 结果大概: (0.6, 0.5, -9.8)  —— z 变很大，因为离相机远了
// 注意：相机空间 z 为负表示在相机前方
```

### Step 3: 投影矩阵 → 裁剪空间

```cpp
Mat4 proj = perspective(π/4, 1.5, 0.1, 100);
Vec4f clip = proj * Vec4f(camera, 1.0f);
// 现在 clip = (x_c, y_c, z_c, w_c)
// w_c = -camera.z  —— 距离信息被装进了 w！
```

### Step 4: 透视除法 → NDC

```cpp
Vec3f ndc = {clip.x/clip.w, clip.y/clip.w, clip.z/clip.w};
// x ∈ [-1,1], y ∈ [-1,1], z ∈ [-1,1]
// 近大远小在此发生，因为 w 越大除完越小
```

### Step 5: 视口 → 屏幕像素

```cpp
Mat4 vp = viewport(800, 600);
Vec3f screen = vp.transformPoint(ndc);
// screen.x ∈ [0,800), screen.y ∈ [0,600)
// screen.z ∈ [0,1] 给深度缓冲
```

> **调试建议**：在 `stage05_transform.cpp` 里，选一个顶点跟踪打印每个空间的值。这是理解管线最快的方式。
