# 00 · 学习路线与项目导读

> 这份文档是入口。它告诉你：这套资料讲什么、按什么顺序读、怎么和代码配合、环境怎么搭。读完它，你就有了一张完整的地图。

## 一、这个项目到底是什么

这是一个**用纯 CPU 手写的软光栅渲染器**：不借助 OpenGL / DirectX / Vulkan，把"给一堆 3D 三角形 + 相机 + 光源，算出屏幕每个像素的颜色"这件事从头实现一遍。

这正是显卡内部做的事。我们用 CPU 重写它，唯一目的是**把黑盒拆开看**。每行代码背后都对应一条图形学原理，而本套文档负责把原理讲透。

设计上有两条原则：

- **渲染器本体（`src/`）零第三方依赖**：纯 C++17 标准库，平台无关，任何编译器拿来即用。
- **有成熟开源库就不重复造轮子**：图像加载、模型解析、日志、测试等"非渲染核心"工作直接集成到 `third/` 目录（stb、tinygltf、tinyobjloader、EnTT、spdlog、Google Test），精力全部花在渲染核心算法上。

学习它的价值不在于"造一个能用的引擎"，而在于：当你以后用任何图形 API 时，你会**真正理解**每个函数在管线里处于什么位置、为什么需要它、参数错了会出什么现象。

## 四、项目结构

```
softrender/
├── CMakeLists.txt          构建脚本（示例 + 测试 + 第三方库）
├── src/                    ★ 渲染器本体，纯 C++17，平台无关
│   ├── math/               向量、矩阵、四元数、变换
│   ├── core/               帧缓冲/深度缓冲/颜色、MSAA、后处理、
│   │                       内存池、日志、Profiler、资源管理、命令缓冲
│   ├── raster/             画线、三角形填充、裁剪、Renderer 管线
│   ├── scene/              网格、纹理、相机、OBJ/glTF 加载、
│   │                       ECS 组件、骨骼、粒子、渲染队列
│   ├── shader/             Shader 基类、Phong、PBR、阴影/法线贴图
│   └── test/               内置测试框架与像素回归工具
├── platform/               ★ 平台相关显示层
│   └── win32_window.h      Win32 + GDI 窗口后端
├── examples/               各阶段示例与综合演示
├── tests/                  Google Test 单元测试（71 个用例）
├── third/                  第三方库（EnTT/spdlog/stb/tinygltf/
│                           tinyobjloader/nlohmann/Google Test）
├── cmake/                  安装导出与版本配置
├── output/                 渲染输出图像
└── docs/                   本套学习文档
```

两个星号目录的分层是刻意的设计：`src/` 是平台无关的渲染器库，`platform/` 是"怎么把结果显示出来"的可替换后端。详见 [21 · 项目架构总览](engineering/21-项目架构总览与进阶路线.md)。

## 五、环境搭建与构建

只需要一个 C++17 编译器 + CMake 3.16+。第三方库全部以源码形式放在 `third/`，随项目一起编译，无需额外安装。

```bash
cmake -S . -B build -G "Visual Studio 17 2022" -A x64   # 配置（Windows + VS）
cmake --build build --config Release                     # 编译
./build/bin/Release/stage8_realtime.exe                  # 运行实时演示
./build/bin/Release/unit_tests.exe                       # 运行全部单元测试
```

Linux / macOS 上把生成器换成默认（Ninja 或 Make）即可，渲染器本体无需任何改动：

```bash
cmake -S . -B build
cmake --build build --config Release
```

> 在 Linux/macOS 上 `stage6_realtime` 与 `stage8_realtime` 不会编译（它们依赖 Win32 窗口后端），但所有离屏示例（输出图像）照常工作。这正是平台无关设计的体现。

### 查看渲染结果

离屏示例输出图像到 `output/`（TGA/PNG）。TGA 是最简单的图像格式，多数看图软件能直接打开。若需转 PNG，可用 ffmpeg：

```bash
ffmpeg -y -i output/stage8_final.tga output/stage8_final.png
```

## 六、学习方法建议

1. **先跑起来，再读原理**。先把 12 个阶段编译运行一遍，看 `output/` 里的图，对"渲染器能做什么"有直观印象，再回头看文档会顺畅得多。
2. **改参数看现象**。文档每节的"动手实验"是精华。比如把透视投影的 `fovY` 从 45° 改成 120°，画面会怎样？为什么？这种"预测—验证"的循环，是真正学会的方式。
3. **不要跳过数学，但也不必卡死**。`math/` 是后面所有内容的语言。第一遍看不懂推导没关系，先记住结论和几何意义，用到时再回来，往往豁然开朗。
4. **对照 GPU 概念**。文档会反复把你的 CPU 代码和 GPU 管线术语对应（顶点着色器、片元着色器、varying、uniform、深度测试……）。学完这套，你看任何 OpenGL / Vulkan / WebGPU 教程都不会再"知其然不知其所以然"。
5. **带着问题读**。每篇开头都点明"它要解决什么问题"。先想"如果是我，我会怎么做"，再看标准答案，印象最深。

## 七、阅读顺序的两种走法

- **系统派**：`pipeline/01 → 09` 顺序读完，数学穿插 `math/`，每篇配对应阶段代码。适合想扎实打基础的人。
- **项目派**：跟着阶段走，做阶段 N 时读它对应的文档（见对照表）。适合喜欢边做边学的人。

两条路殊途同归。无论你选哪条，都从下一篇 `pipeline/01 图形渲染管线全景` 开始——它会给你一张贯穿始终的地图，后面每一篇都是这张地图上某个区域的放大。
