# 渲染数学：从零开始

> 假设你只有高中数学基础。每篇只讲一个概念，讲清楚三件事：**为什么要学它、它到底在干什么、在代码的哪里用到它**。学完这套，你就能看懂这个渲染器里所有的数学代码，并且知道为什么这么写。

## 一、数学在渲染里到底干什么

渲染的输入是一堆三角形（3D 几何），输出是一张 2D 像素图。这两种东西用的"坐标系"完全不同——3D 坐标是无界的浮点数，2D 屏幕是整数像素格。

**渲染数学的本质，就是"坐标系跳转"**。一个顶点要在不同坐标系之间飞来飞去：

```
模型空间（物体自己的坐标）
   ↓ 模型矩阵 → 平移到世界某个位置
世界空间（全局 3D 坐标）
   ↓ 视图矩阵 → 把世界搬到相机眼前
相机空间（从相机位置看）
   ↓ 投影矩阵 → 计算近大远小
裁剪空间（埋好透视伏笔）
   ↓ 透视除法 ÷w → 真正的近大远小在此发生
NDC（规整立方体 [-1,1]³）
   ↓ 视口变换 → 映射到像素
屏幕像素
```

每跳一次就是一次矩阵乘法。这就是为什么**矩阵**是渲染的"通用语言"。而矩阵里的每个元素都是**向量**算出来的。所以学习路径是：

**向量 → 矩阵 → 变换 → 高级技巧**

## 三、怎么读最有效

1. **先跑代码再看文档**。每读一篇，打开对应的 `.h` 文件，找到同名函数，看注释里的公式，然后在测试里写一行调用验证。
2. **几何直觉优先**。公式不重要，重要的是"它在 3D 空间里到底发生了什么"。每篇开头都有"直觉"小节。
3. **遇到代码立刻测试**。`docs/` 旁边就是 `include/softrenderer/`，`tests/` 下有 267 个测试用例 / 60 个套件。每读完一篇，跑一遍对应的测试：`.\build\bin\Release\unit_tests.exe --gtest_filter="Vec.*"`

## 四、数学基础最少面

你可能忘了三角函数。需要记住的只有两个数：

| angle | sin | cos |
| --- | --- | --- |
| 0° | 0 | 1 |
| 30° | 0.5 | 0.866 (√3/2) |
| 45° | 0.707 (1/√2) | 0.707 |
| 60° | 0.866 | 0.5 |
| 90° | 1 | 0 |

剩下的数，`std::sin/ std::cos` 帮你算。

还需要知道：**cos0° = 1**（同向最多），**cos90° = 0**（垂直），**cos180° = -1**（反向）。点积讲的就是这个。

## 五、每篇文档的结构

每篇分四个层次：

- **直觉**：它在 3D 空间里做了什么？类比现实世界。
- **公式**：数学表达（含完整推导）。
- **对应代码**：指向 `include/softrenderer/math/` 的具体函数和行。
- **动手实验**：改一行代码看效果变化。
