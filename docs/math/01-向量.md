# 01 · 向量

> 向量是渲染里最基础的数据类型——所有坐标、方向、颜色、法线、光线都是向量。本篇回答：向量是什么、怎么表示、怎么做加减法和数乘。

## 一、直觉

### 向量是什么

把向量想象成**一根从原点伸出去的箭**——它有方向，也有长度。

- 方向：它指向哪里
- 长度（也叫模、范数）：箭头有多长

在渲染器代码里，向量用 `Vec2f / Vec3f / Vec4f` 表示。`f` 代表 `float`（浮点数）。

```cpp
Vec3f pos{1.0f, 2.0f, 3.0f};  // 一个三维向量：(x=1, y=2, z=3)
```

### 向量的三种身份（最容易混淆的点）

同样是一个三元组 `(x, y, z)`，在渲染里可能是三种完全不同的东西：

| 身份 | 例子 | 可以平移吗？ |
|---|---|---|
| **点**（位置） | 顶点坐标 `(1, 2, 3)` | ✅ 平移会改变位置 |
| **方向**（向量） | 法线、光线方向 | ❌ 方向平移到别处还是同一个方向 |
| **颜色** | `(r, g, b)` | 跟空间无关，只是借用了三元组容器 |

代码里它们都用 `Vec3f` 存，**语义靠你脑子里区分**。后面讲的"齐次坐标"会用第 4 个分量 `w` 在数据层面区分点和方向。

### 向量运算的直觉

- **加法 `a + b`**：把 b 的箭接在 a 的箭头上，连起来就是结果。也就是"先走 a，再走 b"。
- **减法 `a - b`**：从 b 的箭头指向 a 的箭头。
- **数乘 `v * 2`**：把箭拉长 2 倍，方向不变。
- **数乘 `v * (-1)`**：反转方向（取反 `-v`）。

## 二、长度的计算

向量 `v = (x, y, z)` 的长度（用 `|v|` 表示）：

$$|v| = \sqrt{x^2 + y^2 + z^2}$$

这是勾股定理的三维版：先算 xy 平面的长度 √(x²+y²)，再用它和 z 一起算总长。

代码里：

```cpp
float len = v.length();    // 长度
float len2 = v.lengthSq(); // 长度的平方（省掉开方，比较时更快）
```

### 单位化（归一化）

把向量缩到长度为 1，方向不变。公式：每个分量除以长度。

```cpp
Vec3f n = v.normalized(); // n 的长度 = 1，方向同 v
```

**为什么需要这个？** 光照计算时用法线和光方向的**单位向量**做点积。如果法线长度不是 1，点积结果会被长度放大，亮度就全错了。

## 三、代码入口

所有向量运算在 `include/softrenderer/math/vec.h`：

| 你想做 | 代码 |
|---|---|
| 创建一个向量 | `Vec3f v{1, 2, 3}` |
| 加法 | `a + b` |
| 减法 | `a - b` |
| 数乘 | `v * 2.0f`（也支持 `2.0f * v`） |
| 长度 | `v.length()` |
| 长度平方 | `v.lengthSq()` |
| 单位化 | `v.normalized()` |
| 取第 i 个分量 | `v[0]`（即 x），`v[1]`（y），`v[2]`（z） |

## 四、动手实验

在 `tests/test_core.cpp` 里找到 `TEST(Vec, NormalizeLength)`，看看它是怎么验证"单位化后长度为 1"的。然后自己写一行：

```cpp
Vec3f v{1, 0, 0};
Vec3f doubled = v * 2.0f;
EXPECT_FLOAT_EQ(doubled.x, 2.0f);  // 这应该通过
```

跑：`./build/bin/Release/unit_tests --gtest_filter="Vec.*"`

## 五、坐标系约定

你看到的 `(x, y, z)` 按这个约定解释：

- **右手坐标系**：拇指 X，食指 Y，中指 Z
- **Y 向上**：世界和屏幕都如此
- **相机看向 -Z**：相机前方是 Z 轴负方向

这些约定贯穿整个渲染器。如果画面颠倒、面反了、深度反了，回来查这张表。
