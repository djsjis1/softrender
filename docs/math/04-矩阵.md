# 04 · 矩阵

> 矩阵是渲染里"把变换装进盒子"的工具——一次乘法，平移+旋转+缩放全搞定。本篇讲清楚：矩阵是什么、为什么是 4×4、乘法顺序为什么重要。

## 一、直觉

想象你要对一堆顶点做三个操作：先旋转、再平移、再缩放。如果对每个顶点都先算出旋转结果、再算平移结果……那每个顶点要做三次运算。

**矩阵的魔法**：把旋转、平移、缩放各自写成矩阵，三个矩阵**乘在一起变成一个**，然后每个顶点只乘一次这个"合成矩阵"就走完了全部变换。这就是"预组合"——场景里有成千上万个顶点，省下的计算是巨大的。

## 二、矩阵乘法：不满足交换律

**A·B ≠ B·A**。在渲染里，这意味着：

```cpp
Mat4 M = translate * rotate;  // 先旋转，后平移
Mat4 M = rotate * translate;  // 先平移，后旋转  —— 效果完全不同！
```

为什么？后一种会"绕世界原点转"，不是绕物体自己的中心转。这是新手最常掉的坑。

### 乘法顺序的口诀

**写在右边的先执行。** 想"先转后移"，就写 `Translate * Rotate`——因为 Rotate 离向量更近，对每个顶点先作用。

```cpp
Mat4 mvp = proj * view * model;  // 先 model，再 view，最后 proj
Vec4f result = mvp * Vec4f(position, 1.0f);
```

在这个渲染器里，矩阵用**行主序**（`m[行][列]`）存储，和 OpenGL 教程常见的列主序相反。但只要乘法定义自洽，结果就正确。

## 三、为什么是 4×4

3×3 矩阵能表示旋转和缩放，但**表示不了平移**——因为平移不是线性变换（它把原点挪走了，f(0)≠0）。

解决办法是**齐次坐标**：给向量加第 4 个分量 `w`，变成 `(x, y, z, w)`。平移量藏在 4×4 矩阵的**第四列**：

```
| 1 0 0 tx |   | x |   | x + tx |
| 0 1 0 ty | × | y | = | y + ty |
| 0 0 1 tz |   | z |   | z + tz |
| 0 0 0 1  |   | 1 |   | 1      |
```

这就是 `Mat4::translate(tx, ty, tz)` 的实现。

## 四、矩阵里有什么

`mat4.h` 提供的工厂函数：

| 函数 | 做什么 | 哪些元素变了 |
|---|---|---|
| `translate(x,y,z)` | 平移 | 第四列 `m[0..2][3]` |
| `scale(sx,sy,sz)` | 缩放 | 对角线 `m[0][0]`, `m[1][1]`, `m[2][2]` |
| `rotateX(rad)` | 绕 X 轴转 | 右下 2×2 子矩阵 |
| `rotateY(rad)` | 绕 Y 轴转 | 四角的 2×2 子矩阵 |
| `rotateZ(rad)` | 绕 Z 轴转 | 左上 2×2 子矩阵 |

## 五、代码入口

| 操作 | 代码 |
|---|---|
| 创建平移矩阵 | `Mat4::translate(1, 2, 3)` |
| 创建旋转矩阵 | `Mat4::rotateY(3.14f/2)` |
| 矩阵相乘 | `proj * view * model` |
| 矩阵乘向量 | `mvp * Vec4f(pos, 1.0f)` |
| 变换点（w=1） | `matrix.transformPoint(point)` |
| 变换方向（w=0） | `matrix.transformDir(direction)` |
| 求逆矩阵 | `matrix.inversed()` |

## 六、动手实验

在 `stage3_cube.cpp` 里把 `model = rotateY * rotateX` 改成 `rotateX * rotateY`——立方体的姿态会不同。体会"顺序不可交换"。
