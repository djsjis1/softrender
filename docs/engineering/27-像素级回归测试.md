# 27 · 像素级回归测试

> 单元测试验证局部契约，像素回归锁定指定场景的最终图像。它能发现覆盖场景中的视觉变化，不能替代未覆盖效果和输入格式的测试。

## 一、工作流程

1. **建立基准**：维护者审核固定场景结果后，显式启用 `SR_UPDATE_GOLDEN` 创建缺失图像。普通测试运行不会自动建立基准。
2. **后续运行**：渲染同一场景，逐像素对比输出与基准图。
3. **判定**：不匹配像素 < 0.1% 且平均差 < 0.5 灰度 → 通过。

## 二、容差设计

为什么允许少量偏差？

- 浮点精度：不同编译器/优化级别可能产生 ±1 灰度差异
- 抗锯齿：MSAA/FXAA 的亚像素采样对浮点顺序敏感
- 平台差异：Linux vs Windows 的 `std::sin` 实现可能差 ULP

所以阈值设为 2 灰度/像素、0.1% 像素不匹配率。超过即为**真回归**。

| 概念 | 代码 |

### ⚠️ 两个曾导致「永远假通过」的陷阱（已修）

工具写好后曾长期**零引用**、`tests/fixtures/golden/` 为空，接线时发现两个叠加起来
会让测试永远绿灯的陷阱：

1. **硬编码相对路径**。旧版写的是 `"tests/fixtures/golden/" + name + ".tga"`，只有从
   仓库根目录运行才正确。而 `ctest --test-dir build` 的工作目录是 `build/`，
   会解析成 `build/tests/fixtures/golden/` → 找不到基准图。
   **现由 CMake 用 `file(TO_CMAKE_PATH)` 注入绝对路径 `SR_GOLDEN_DIR`**。
2. **基准图不存在时自动创建并返回 `passed = true`**。叠加第 1 条 →
   测试永远假通过，比没有测试更危险。
   **现改为由 `SR_UPDATE_GOLDEN` 开关控制**：默认（CI）下缺失直接失败
   并输出绝对路径 + 修复指引；仅本地更新基准时才用
   `cmake -S . -B build -DSR_UPDATE_GOLDEN=ON`。

已做**反向验证**：把一张基准图重命名走后，测试输出
`[REGRESSION] MISSING golden image: <绝对路径>` 并 FAILED（退出码 -1）。

另有 `PixelRegression` 单元套件（7 个用例）验证 `compare()` 本身的判定逻辑 ——
若它恒返回 true，三个集成场景就全是假通过。其中
`compare_uniformSmallDrift_failsOnAvgDelta` 验证「平均差 < 0.5」能**单独**触发失败：
全图每像素只差 1 时，无任何像素超单像素阈值，但系统性偏移仍必须被拦下。

## 四、CI 集成

基准图路径是编译期绝对路径，所以 **ctest 的工作目录不影响结果**：

```yaml
- name: Pixel regression
  run: ctest --test-dir build -C Release -L regression --output-on-failure
```

本地只跑像素回归：

```powershell
ctest --test-dir build -C Release -L regression --output-on-failure
# 或直接跑二进制
.\build\bin\Release\render_regression.exe
```

### 基准图维护

有意变更渲染输出时（例如 TASK-003 把 alpha 混合从截断改成四舍五入，
所有混合结果可能 +1）：

1. `cmake -S . -B build -DSR_UPDATE_GOLDEN=ON` 重新配置
2. 跑一次 `render_regression` 生成新基准图
3. **提交前把开关关掉**（`-DSR_UPDATE_GOLDEN=OFF`），否则缺失基准图会被静默创建
4. 把新 `tests/fixtures/golden/*.png` 与代码改动一起提交，并在 commit 信息里
   说明视觉变更原因

基准图提交到 Git（TGA 无损，体积可控）。若 PR 改变了画面，CI 会报出差异像素数和最大偏差。

## 五、扩展方向

- **SSIM 指标**：比逐像素差更符合人眼感知
- **差异可视化**：输出 diff 图（红=偏差大）方便人工审查
- **多平台基准**：每个 OS 维护自己的 golden 集
