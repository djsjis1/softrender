# 26 · 内存池分配器

`sr::ArenaAllocator` 为同一帧内生命周期一致的临时数据提供原始存储。已有块足够时，分配只做对齐与游标移动；需要扩容时仍会申请堆内存。`reset()` 为 O(1)，保留内存块以便下一帧复用。

## 使用与生命周期

```cpp
sr::ArenaAllocator arena(4096);
float* values = arena.allocArray<float>(128);
if (values) {
    for (size_t i = 0; i < 128; ++i) values[i] = 0.0f;
}
// 本帧所有使用者结束后显式重置。
arena.reset();
// values 从这里开始不得再使用。
```

分配器**不提供**每线程全局实例：需要时由调用方自己持有（每个工作线程一个），并在帧末显式 `reset()`。它不是线程安全的共享分配器。

定位限度：`ArenaAllocator` 内部经 `new` / `std::vector` 取块，因此它本身依赖堆，**不是裸机零堆方案**。裸机要把帧内存放到指定地址，用渲染目标的外部存储构造（`Framebuffer` / `DepthBuffer` / `FloatFramebuffer` 均已提供）。

`allocArray<T>` 只提供存储，不负责构造或析构 T。非平凡对象需要调用方显式管理对象生命周期；跨帧资源应使用独立 RAII 所有者。

## 参数与失败语义

| 情况 | 行为 |
| --- | --- |
| 初始容量为 0 | 采用最小非零块，仍可扩容 |
| align 为 0 或不是 2 的幂 | 返回 nullptr，不改变游标 |
| 字节数、对齐填充或数组元素乘法溢出 | 返回 nullptr，不改变游标 |
| 合法的过对齐要求 | 通过块内填充满足对齐 |
| 系统内存不足 | 标准分配异常继续传播，RAII 防止泄漏 |
| size 为 0 | 提供可对齐的零长度位置，不保证不同调用地址不同；不可解引用 |

`used()` 表示本帧实际分配及对齐填充的字节数；`capacity()` 表示所有保留块的字节总数。二者不同：当前块尾部碎片不记入 used，但计入 capacity。

## 扩容和复用

块用 `unique_ptr` 管理，vector 扩容失败不会泄漏刚申请的内存。尺寸运算先校验，再通过 `std::align` 在已知合法的缓冲区内对齐，避免先形成越界指针再比较。

reset 后从第一块重新分配；扩展块按顺序复用，不再每帧 delete/new。相同分配序列的稳态帧不会新增内存块。通常分配为 O(1)；一次请求跨过多个较小的保留块时，查找开销与跨过的块数相关。

代价是**保留峰值容量直到析构**。处理偶发巨型数据时，使用短生命周期分配器释放峰值；长期每线程实例应通过 capacity() 观测内存占用。本轮没有增加自动收缩机制。

## 验证

`tests/unit/arena_test.cpp` 覆盖零容量、非法对齐、算术溢出、过对齐、跨块写入及 100 次重复帧复用。性能结论是“消除了重复负载的块分配/释放”，没有宣称整体 FPS 或固定微秒级收益；需要在真实渲染工作负载下单独测量。
