# 48 · 性能优化指南

> 软渲染器热点随几何、着色与分辨率变化，应先测量当前场景。本篇总结已实施的优化和进一步优化方向。

## 一、已实施的优化

| 优化 | 位置 | 效果 |
|---|---|---|
| 增量式边函数 | `renderer.h` | 整数覆盖与浮点插值分别增量递推 |
| 增量式深度 | `renderer.h` | 每像素 1 加法代替 3 乘 2 加 |
| 包围盒裁剪 | `renderer.h` | 只遍历三角形 AABB 内像素 |
| 背面剔除 | `renderer.h` | 先跳过背面，再建立覆盖方程；比例取决于场景 |
| SSE2 四像素并行 | `rasterizer_fast.h` | 4 像素同时判定内外 |
| 多线程分条 | `stage14_threaded` | N 线程并行光栅化 |
| 命令缓冲并行 | `command_buffer.h` | 无依赖命令并行回放 |
| 线程池 | `command_buffer.h` | 避免每帧创建/销毁线程 |
| 内存池 | `arena.h` | 常规游标分配与 reset 复用；扩容有额外成本 |

## 二、增量边函数原理

边函数 $E_i(x,y) = \text{cross2}(\text{edge}_i,\; p - v_i)$ 对 $x,y$ 是线性的：

$$\frac{\partial E_i}{\partial x} = -(v_{next}.y - v_{cur}.y)$$
$$\frac{\partial E_i}{\partial y} = +(v_{next}.x - v_{cur}.x)$$

预计算后，覆盖使用 int64 增量和 top-left 偏置；浮点边式另外递推用于属性插值，不能再把整个循环说成只有三次加法。

**重心坐标**只在内部像素从边函数值算（3 次乘法），**深度**也用增量递推（1 次加法）。

## 三、当前瓶颈（2026-10-25 实测）

1080p 整帧 193 ms 的构成：3D 光栅 31 ms、2D 叠加 5 ms、**后处理 157 ms（81%）**。

| 项 | 1080p 耗时 | 说明 |
|---|---|---|
| SSAO 全分辨率（16 样本） | 596 ms | 随机深度采样；瓶颈是 8 MB 深度图的 cache miss |
| SSAO 半分辨率 | 218 ms | 与全分辨率平均差 4e-6 |
| FXAA | 156 ms | 已做亮度图预计算、整行拷贝、延迟角落读取 |
| Bloom 链（bright + blur + add + resolve） | 293 ms | 高斯模糊全屏多次核采样 |

几何侧没有峭壁：640×360 与 4K 的每像素成本基本持平（54 vs 56 Mpix/s），
1080p 纯 3D 填充 67 Mpix/s、小三角形 3.0 Mtris/s。

结论：**慢的不是渲染器本体，而是按全分辨率逐像素跑的后处理**。关掉后处理，
1080p 立即从 5 fps 回到 32 fps。

## 四、两条提速路线

同一个问题有两条路径，改动量差两个数量级。两条都**未实施**，本节只记录评估结论。

| | A. 主链路 SIMD 化 | B. 后处理降分辨率 |
|---|---|---|
| 做法 | 把 `rasterizer_fast.h` 的 SSE2 四像素路径接进 `Renderer`，Shader 改为批量输出 | 效果先在半/四分之一分辨率计算，再上采样回全屏 |
| 为何现在没接 | `rasterizer_fast` 只接受单一 `Color`，不支持 `Varyings` 插值与 `Shader::fragment` 回调 | — |
| 涉及范围 | `render/pipeline/renderer.h` + 全部内置 Shader 的输出契约 | `render/postprocess/post_processing.h` + 调用处 |
| 现有基础 | 实验版光栅器（未接入主链路，见 `architecture.md` §6.1） | SSAO 已有 `computeHalfResolution`，其余照搬 |
| 风险 | 高：接口级改动，错色/漏像素难定位 | 低：最差只是边缘变软 |
| 收益 | 所有分辨率、所有着色路径 | 只覆盖后处理段（当前占整帧 81%） |
| 回滚 | 难（接口变更） | 容易（改回一个参数） |

取舍：B 是拿画质换速度，改动小、可回滚，能把 1080p 整帧从 193 ms 压到约 60 ms；
A 是改渲染器骨架，收益覆盖全链路，但需要先立 ADR 定下 Shader 的批量输出接口，
再按 Shader 逐个迁移。

## 五、进一步优化方向

| 方向 | 预期收益 | 复杂度 |
|---|---|---|
| AVX2 八像素并行 | 需测量，受指令与访存瓶颈影响 | 中 |
| Tile-based 光栅化 | 缓存友好，减少 depth buffer 带宽 | 高 |
| 遮挡优化 | 现有 Renderer 已先做深度比较，可继续评估层次遮挡 | 中 |
| 层次 Z-buffer | 大块跳过完全被遮挡的区域 | 高 |
| 透视校正增量 | 避免内部像素的除法 | 中 |
| SIMD 深度测试 | 4/8 像素同时比深度 | 中 |
| 三角形 setup 优化 | 共享整数覆盖已实现，后续需测量 setup/像素阶段占比 | 中 |

## 六、性能测量

整帧比较优先使用[固定场景基线](58-覆盖规则与性能基线.md)。旧 Bench 可用于局部实验，但下列重复绘制会受已有深度遮挡影响，测量完整帧时每次必须清屏：

```cpp
#include <softrenderer/core/benchmark.h>

SR_BENCH_RUN("rasterize_1000_tris", [&]() {
    renderer.clear(fb, colors::black);
    renderer.drawMesh(fb, mesh, shader);
}, 100);

sr::Bench::instance().report();
```

## 七、Profiler 建议

- **Windows**：Visual Studio Profiler 或 Tracy
- **Linux**：perf + flamegraph
- **跨平台**：Tracy（开源，实时，低开销）

热点通常在：

1. 片元着色器（PBR 计算量大）
2. 深度测试（内存带宽）
3. 透视校正插值（除法）
