# 裸机（无操作系统）集成指南

> 决策背景见 [ADR-007-baremetal-freestanding](../adr/ADR-007-baremetal-freestanding.md)。
> 承诺范围：**core + math + render + resource + scene** 五个组件（全部 header-only）。
> io（第三方解析器）、runtime（线程/日志）、platform（窗口）依赖宿主设施，不参与裸机构建。

## 1. 组件裁剪构建

```sh
cmake -S path/to/softrender -B sr-build -DSR_NO_EXCEPTIONS=ON
cmake --install sr-build --config Release --prefix ./sr-install
```

`SR_NO_EXCEPTIONS=ON` 时：

- core 接口自动携带 `-fno-exceptions -fno-rtti`（MSVC 仅 `/GR-`，其 STL 不支持关异常）；
- io / runtime / tests / examples / practice / benchmarks 自动关闭（它们依赖异常或宿主设施）；
- 下游 target 链接 `SoftRenderer::core` + `SoftRenderer::render`（或 `::scene`）即可继承同一套编译标志。

## 2. 外部存储：渲染缓冲不经堆

裸机上通常把帧缓冲放进静态内存、内存池或指定 RAM 段。三个类都提供
非拥有的外部存储构造：

```cpp
// 缓冲放在链接脚本指定的段 / 静态内存，容量 = w*h*kBytes 与 w*h*float
static Color    g_pixels[W * H];
static float    g_depth[W * H];

sr::BasicFramebuffer<sr::Color> fb(W, H, g_pixels);   // 8 位格式同理换 PixelT
sr::DepthBuffer                 depth(W, H, g_depth);
sr::Renderer                    renderer(W, H, g_depth);

// 之后照常使用；构造零分配，析构不释放（存储归调用方所有）
renderer.clear(fb, sr::colors::black);
renderer.drawMesh(fb, mesh, shader);
```

契约：

- 外部存储构造**不做填充**：首帧前请自行 `clear()`；
- `storage` 须能容纳 `w*h` 个像素/float，并满足对齐（`Color` 4 字节对齐、`float` 天然满足）；
- 生命周期必须覆盖缓冲对象；析构不释放（`owns_` 标志区分）；
- 对象可移动（转移指针与所属权），不可拷贝。

深度测试结果直接落在调用方存储里（`renderer.depth()` 与外部存储同址），
方便把深度图复用为阴影贴图。

### 2.1 零堆渲染的完整清单

`drawMesh` 内部有顶点缓存（共享顶点只着色一次），默认用内部 `std::vector`
（首次分配堆）。零堆路径需把顶点缓存也换成外部存储：

```cpp
static sr::ClipVertex g_vcache[MAX_VERTS];   // 容量 >= 所有网格的顶点数
static uint32_t       g_vstamps[MAX_VERTS];
renderer.setExternalVertexCache(g_vcache, g_vstamps, MAX_VERTS);
// 容量不足的网格自动回退内部 vector（正确性不变，但会走堆）
```

HDR 路径同理：`FloatFramebuffer(W, H, Vec3f* pixels)` 或
`FloatFramebuffer(W, H, Vec3f* pixels, float* depth)`，像素与深度都可外部。
外部存储的 FloatFramebuffer 是**定尺寸**的：`resize` 到不同尺寸为空操作
（自分配版本才会重建），后处理整链函数（`bloom`/`gaussianBlur` 等内部
会 resize 的）不适用于外部存储——请用 `*Rows` 行区间算子自行编排。

### 2.2 零堆证明（主机上可复现）

`ctest -R baremetal_smoke`（源码 `tests/integration/baremetal_smoke.cpp`）：
全局 `operator new` 熔断守卫开启期间连续渲染两帧，任何分配请求都会置
违规计数并判失败。该测试只链接 `SoftRenderer::core + SoftRenderer::render`，
兼作组件边界验证。裸机整链零分配的承诺以此用例锁定——公共头新增任何
渲染期堆依赖（如临时 `std::vector`）都会在这里被抓住。

## 3. 异常与 RTTI

- 五个组件的公共头**零 `throw`、零 `dynamic_cast`/`typeid`、零线程/文件头**；
  由 `sr_freestanding_headers_check` 门禁在 GCC/Clang 上逐头以
  `-fno-exceptions -fno-rtti` 编译强制（CI Linux 作业执行）。
- 错误报告走返回值与断言（ADR-002），不依赖异常传播。
- MSVC 下 `/GR-` 可用；`-fno-exceptions` 因其 STL 限制仅在 GCC/Clang 验证。

## 4. 像素格式建议（嵌入式面板）

| 目标设备 | 推荐缓冲 | 说明 |
| --- | --- | --- |
| ILI9341 / ST7789（RGB565） | `BasicFramebuffer<sr::Color565>` | 2 字节/像素，渲染直落面板格式（ADR-005） |
| 单色 OLED | `BasicFramebuffer<sr::Gray8>` | 8 位灰度 |
| 通用 | `sr::Framebuffer`（RGBA8888） | 与示例/回归基准同格式 |

渲染输出为 `Vec3f` 运算域，量化只发生在 `Pixel::fromFloat` 一处——
同一份 shader 与覆盖规则在所有格式下逐位一致（`pixel_format_test` 锁定）。

## 5. 主机上的等价验证

裸机构建裁掉了 tests，主机侧完整验证仍覆盖同一条代码路径：

```sh
ctest --test-dir build -C Release -L "fast|regression"   # 单测 + 像素回归 + 零堆 smoke
```

外部存储、免堆渲染与自分配路径的逐像素一致性由
`RendererBaremetal` / `DepthBuffer.externalStorage_*` /
`Framebuffer.externalStorage_*` / `FloatFramebuffer.externalStorage_*` 用例
锁定；`baremetal_smoke` 用 operator new 熔断证明整帧渲染零分配（§2.2）。
