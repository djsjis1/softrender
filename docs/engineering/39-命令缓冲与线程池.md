# 39 · 命令缓冲与线程池

接口位于 `include/softrenderer/runtime/command_buffer.h`，类型为 `sr::CommandBuffer` 和 `sr::ThreadPool`。
错误与生命周期决策见 [ADR-002](../adr/ADR-002-data-and-task-errors.md)。

## 命令回放

```cpp
sr::CommandBuffer commands;
commands.record([&] { renderLeftTile(); });
commands.record([&] { renderRightTile(); });
try {
    commands.executeParallel(4);
} catch (const std::exception& error) {
    report(error.what());
}
```

回调只能写互不重叠的存储，或自行同步。绘制不同物体仍可能竞争同一个颜色/深度像素。
命令执行期间不能 record、clear、销毁或再次执行同一缓冲。

`record` 拒绝空回调。`executeSequential` 遇到异常立即停止并向调用者抛出；
`executeParallel` 尝试全部命令，等待线程结束后报告首个捕获的异常，即使指定一个线程也遵循该语义。
首个异常由实际调度顺序决定。线程创建失败会回收已启动线程并报告创建错误，不能保证尚未启动的命令全部执行。
并行回放使用调用线程参与工作，总执行线程数不超过请求值和命令数的较小值。

## 普通任务与结果任务

```cpp
sr::ThreadPool pool(4);
pool.submit([&] { updateIndependentResource(); });
try {
    pool.waitAll();
} catch (const std::exception& error) {
    report(error.what());
}

auto result = pool.submitFuture([data = std::make_unique<int>(42)] { return *data; });
int value = result.get(); // 返回 42；任务异常也从这里报告
```

| 接口 | 完成与错误语义 |
| --- | --- |
| `submit` | 成功返回表示入队；空回调同步抛出 invalid_argument |
| `waitAll` | 等待队列和活动任务同时为空，再消费首个尚未报告的 submit 异常；后续调用不会重复报告它 |
| `submitFuture` | 支持返回值及移动捕获；错误只保存在该 future 中，必须 get 才会重新抛出 |
| 析构 | 排空已接受任务并 join；不报告任务异常 |

多个生产者可并发提交。`waitAll` 是某个空闲时刻的观测，不阻止其他线程随后提交新任务；
若多个线程同时等待，只有一个等待者消费池中保存的异常。需要逐任务错误时使用 future。
future 就绪表示函数已返回；需要确认捕获资源已释放时再调用 waitAll。

## 生命周期边界

- 捕获的引用和渲染目标必须活到任务结束；所有权宜通过值或智能指针捕获。
- worker 调用自己所属池的 waitAll 会得到 logic_error，避免直接自等待死锁。
- 不得在 worker 中销毁所属线程池，也不要阻塞等待必须由同池排队任务完成的 future。
- 析构期间不能再并发调用该对象；没有取消、强制停止或超时终止功能。
- 构造部分失败时停止并 join 已创建线程，再向构造者抛出原异常。
