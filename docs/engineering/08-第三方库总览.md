# 08 · 第三方库：清单、集成与管理策略

> 所有第三方库统一放在 `third/` 目录，通过 CMake `add_subdirectory` 或静态库集成。核心光栅化与数学（`include/softrenderer/math/`、`render/raster/`）不依赖第三方；场景加载与 ECS 依赖仓库内置第三方代码。

## 一、核心原则

1. **核心光栅化与数学零第三方依赖**——纯 C++23 标准库，任何平台编译即用。其余模块（图像加载、glTF、ECS）依赖仓库内置第三方代码，完整说明见 [architecture.md](../architecture.md)。
2. **第三方库源码放在 `third/`**——不要求用户手动安装，`add_subdirectory` 一键集成。
3. **使用层（examples/）可选依赖**——通过 CMake option 控制是否启用。
4. **版本锁定**——`third/` 里放的是确定版本的源码快照，不用 git submodule。

## 三、编译组织

所有需要 `.cpp` 实现的库统一编译为一个静态库 `third_party_impl`：

- `src/io/stb_impl.cpp`（含 stb_image + stb_image_write 实现）
- `src/io/tinygltf_impl.cpp`（含 tinygltf 实现）
- `src/io/tinyobj_impl.cpp`（含 tinyobjloader 实现）

header-only 库（EnTT）用 INTERFACE 目标，测试框架用 `add_subdirectory` + `EXCLUDE_FROM_ALL`，日志经 `third/log/CMakeLists.txt` 封装。

## 四、添加新库的流程

1. 下载源码快照到 `third/<lib-name>/`
2. 确认其 `CMakeLists.txt` 支持 `add_subdirectory`；需要编译实现的，创建 `*_impl.cpp` 并加入 `third_party_impl`
3. 在主 `CMakeLists.txt` 加 `option(SR_ENABLE_XXX ...)` + `add_subdirectory`，必要时提供 `sr_enable_xxx(target)` 辅助函数
4. 渲染器本体通过条件编译（`#ifdef SR_USE_XXX`）可选使用
5. 更新 `install.cmake` 与本文档

## 五、为什么不 git submodule

- CI 环境可能无网络
- submodule 更新不可控（上游 force push 会破坏构建）
- 源码快照 = 构建可复现性

代价是更新时需手动替换目录。对渲染器这种低频依赖更新的场景完全可接受。

## 六、tinyobjloader（OBJ 加载）

OBJ 模型解析不是渲染原理，是文件格式解析，直接用单头文件的 **tinyobjloader**。

源码 `third/tiny_obj_loader.h`，实现 `src/io/tinyobj_impl.cpp`。

```cpp
#include <softrenderer/io/obj_loader.h>
Mesh mesh;
std::string error;
if (objloader::load("model.obj", mesh, &error)) { /* 使用 mesh */ }
```

内部调用 `ObjReader::ParseFromFile`，自动三角化多边形并转换为 `Mesh`。相比自写解析器的优势：支持 mtllib/usemtl、负索引、多边形自动三角化，错误报告更完善，C 风格解析无 map 查找开销。
