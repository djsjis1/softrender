# 59 · 全仓缺陷审查记录（2026-10-25）

> 本篇是一次完整审查的结论归档：按「怎么找 → 找到什么 → 改了什么 → 没改什么 → 怎么验证」
> 组织。逐轮过程见 [changelog](../changelog.md)，当前数值见 [project_context](../project_context.md)。

## 一、方法

本次审查用了四种互补的手段，因为单一手段会留下盲区：

| 手段 | 能发现 | 发现不了 |
| --- | --- | --- |
| 逐函数读实现 | 逻辑错误、契约不一致、掩盖链 | 未被执行过的分支 |
| 调用方清点（grep 每个导出函数） | 零调用的"未验证 API" | 实现内部错误 |
| Debug + ASAN 全量运行 | 越界、UB、断言触发 | 只有在特定输入下才触发的逻辑错 |
| 对照既有测试 | 把"设计差异"误判成"缺陷" | 测试本身没覆盖的行为 |

关键经验：**Release 全绿不等于安全**。本次最隐蔽的一个缺陷（`computeShadow`）
在 Release 下结果完全正确，只在 Debug 触发断言——因为下游还有一层兜底把它遮住了。

## 二、修复清单（17 项）

每项都有可复现的失败证据，修复后由新增或既有用例锁定。

### 输入与尺寸

| # | 位置 | 缺陷 | 表现 | 验证 |
|---|---|---|---|---|
| 1 | `core/depthbuffer.h`<br>`core/float_framebuffer.h` | 构造器不校验尺寸，`size_t(width) * height` 把负数转成 ~2^64 | 抛 `length_error`，而 `resize()` 对同类输入只是忽略 | 构造器与 resize 口径统一为「任一边非正 → 0×0」 |
| 2 | `render/draw2d/shape2d.h` `fillPolygon` | 缺 `allFinite` 前置校验 | NaN 顶点让 `(int)std::floor(NaN)` 进入 UB | 补校验；钳制范围改为屏幕范围（见下条） |
| 3 | 同上 | 初版钳到 1e7 消除 UB 但产生千万次无效循环 | 64×64 场景耗时 1.2 s | 改为钳到屏幕尺寸，0.12 ms |
| 4 | `render/postprocess/post_processing.h` `chromaticAberration` | 用调用方传的 `W/H` 索引 `src.getPixel` | 尺寸不符时越界读；输出不重建 | 以 `src` 实际尺寸为准并重建 `out` |

### 数值与退化输入

| # | 位置 | 缺陷 | 表现 | 验证 |
|---|---|---|---|---|
| 5 | `render/shader/pbr_shader.h` | `roughness = 0` 时 `a2 = 0`，GGX 的 D 恒为 0 | **完美镜面反而没有高光**，与注释「0=镜面」相反 | 取感知粗糙度下限 0.04 |
| 6 | `render/shader/deferred_lighting.h` | 同上（BRDF 的复制品，修 5 时漏掉） | 延迟渲染路径仍是旧行为 | 同下限 |
| 7 | `scene/camera.h` `projMatrix` | 退化参数无防护（`aspect=0`、远近平重合） | 产出 inf/NaN 投影，整帧几何被静默丢弃 | 参数夹到可用范围 |
| 8 | `scene/camera.h` `right` | `pitch = ±90°` 时叉积为零向量 | 归一化得 NaN，view 矩阵跟着坏 | 改用 `normalizedOr` |
| 9 | `math/quat.h` `fromAxisAngle` | 零/非有限轴无防护 | NaN 四元数沿蒙皮链污染整帧矩阵 | 退化输入返回单位四元数 |
| 10 | `resource/texture_generator.h` `normalMapBumps` | `strength` 只查 `isfinite`，极大值上溢 | `uint8_t(NaN)` 是 UB，部分像素解码后不是单位法线 | 强度夹到 `[0, 100]` |

### 越界与生命周期

| # | 位置 | 缺陷 | 表现 | 验证 |
|---|---|---|---|---|
| 11 | `render/shader/advanced_shaders.h` `computeShadow` | 边界检查用成员 `shadowW/H`，却访问 `shadowMap` | Release 靠 `get` 兜底「碰巧正确」；**Debug 断言中止** | 采样范围改用 map 自身尺寸 |
| 12 | `resource/mesh.h` `computeTangents` | 直接 `vertices[indices[i]]`，不校验范围 | Debug 报 `vector subscript out of range`；Release 静默越界写 | 逐三角形校验三个索引 |
| 13 | 同上 | 切线与法线平行时兜底成固定 `(1,0,0)` | 若法线接近 +X，TBN 仍然退化 | 两条分支共用 `orthogonalTangent` |

### 契约与一致性

| # | 位置 | 缺陷 | 表现 | 验证 |
|---|---|---|---|---|
| 14 | `render/pipeline/render_queue.h` | `sortKey()` 按 uint16 截断 `materialId`，比较器用有符号比较 | 负材质时两个入口给出**相反顺序** | 比较器改用同口径 |
| 15 | `render/draw2d/shape2d.h` `drawLineDashed` | `period = dash + gap` 无下限 | `(0,0)` 时整数除零（UB），实测一个像素都不画 | `period >= 1` |
| 16 | `render/draw2d/shape2d.h` `drawLineThick` | `-half..half` 铺线，偶数厚度多画一条 | `thickness=4` 画出 5 像素宽 | 改用 `lo..hi`，并夹到画布尺寸 |
| 17 | `runtime/profiler.h` `~ProfileScope` | `endScope()` 内的字符串拷贝与 `push_back` 可能抛 `bad_alloc` | 从析构逸出即 `std::terminate`，调用方无法捕获 | 析构内捕获全部异常（剖析是辅助功能，不能因此终止进程） |

另有 2 处测试判定问题：

- `draw_call_overhead` 用固定 `200 μs/draw` 判定，Debug+ASAN 下必然误报（实测 217 μs）；
- 上者与 `frame_budget_1080p` 同属「用绝对耗时做正确性判据」这一类，已分别改为校验输出有效性。

## 三、只文档化、未修改的取舍（3 处）

审查中遇到一些「看起来像缺陷、实际是有意设计」的地方。判断依据是**看既有测试锁定了什么**。

| 位置 | 现象 | 判断 |
|---|---|---|
| `runtime/command_buffer.h` | 串行遇异常立即中止，并行会跑完剩余命令 | **有意设计**：并行命令互不相干，各自完成更有用。既有用例 `executeParallel_failure_attemptsAllCommandsEvenWithOneThread` 明确锁定。改为把差异写进两个函数的注释，并补上此前缺失的串行侧用例 |
| `runtime/profiler.h` | `setEnabled` 运行期切换会让 scope 栈失衡 | **取舍**：修法是让关闭路径也入栈，会破坏「关闭时零分配」的目标（`profiler_disabled_overhead` 专门在测这个）。写进注释作为限制 |
| `scene/keyframe_animation.h` | 全仓零引用，与 glTF 那套动画功能重叠 | **遗留**：已作为公共头发布，删除属接口级变更。补状态标注；其除法经二分不变式分析确认除零不可达 |

## 四、原本列为「未完成」的四项，现在的结果

先纠正一条错误结论：之前写「本机无 LLVM 工具链」是没有实际查找就沿用的旧记录。
`VC/Tools/Llvm/x64/bin` 下有 **clang-tidy 19.1.5**，只是没有装 clang 编译器。

| 项 | 状态 | 具体结果 |
|---|---|---|
| clang-tidy 全仓扫描 | **已完成** | 65 个公共头全扫，启用 `clang-analyzer-*` 与 `bugprone-*`：139 条诊断。其中 **1 项真实缺陷已修**（`~ProfileScope` 可能从析构抛 `bad_alloc` 导致 terminate），16 项逐条核实为范围受控的误报，122 条 `narrow-conversions` 为刻意的 `float→int` |
| Windows 窗口示例交互 | **已完成（3/3）** | 三个窗口全部桌面自动化实跑：`stage10_shadow_live` WASD 引起 **61.7%** 像素变化（无输入基线 4.7%）、B 键切换阴影；`stage03_sprite_anim` 空格跳跃使铠甲上移 **112px**（源码峰值为 90px，含窗口缩放换算）后落地、阴影随之缩放；`stage08_shader_live` 的 1/2/3 切换使标题在 Phong→Flat→Gouraud→Phong 间变化，画面差异 **34–37%**，同模式往返基线仅 3.4%。三者均可用 Esc 退出（stage08 在 15–55 FPS 下需按住 ≥300 ms，否则被轮询漏掉） |
| 行 / 分支覆盖率 | **仍不可得（已排除五条路径）** | ① BuildTools 无 `CodeCoverage.exe`；② `dotnet-coverage 18.12` 对原生进程报「探查器未初始化」（专门配 `build-cov` 生成 PDB 后仍如此）；③ LLVM 组件只有 clang-tidy/format，无 `clang-cl` 与 `llvm-cov`；④ `winget` 源更新失败，装不上 OpenCppCoverage；⑤ MSVC bin 下无 `vsinstr.exe` / `VSPerfCmd.exe`。**替代证据**：对 65 个公共头做 include 可达性分析（从 `tests/` 与 `benchmarks/` 的全部 TU 出发做 BFS），**63 个可达**；不可达的 2 个均为非功能头（`core/namespace.h` 是空命名空间文档锚点，`scene/keyframe_animation.h` 是已标注的遗留零引用头）。这只能证明“被测试编译到了”，**不等于行覆盖** |
| macOS / Linux 远端 CI | **仍不可得** | GitHub API 只读可用（能查到历史 run），但 `git push` 三种方式均失败（默认、`HTTP/1.1`+大缓冲、`sslBackend=schannel`），症状一致为 `Could not connect to github.com:443`。值得记录：同刻 `Test-NetConnection github.com -Port 443` 返回 **True**，而 `Invoke-RestMethod api.github.com` 也成功——说明不是全链路断网，而是 **git.exe 进程无法建立到 github.com:443 的连接**，本机无法自行绕过 |

## 六、结论

- 65 个公共头逐个读过，87 个自由函数做过调用方清点；17 项缺陷全部修复并有用例锁定。
- 审查本身也有一次误判被既有测试拦下（`command_buffer` 语义），说明**测试在起实际作用**，
  不只是覆盖率数字。
- 最有价值的副产品是方法：调用方清点找「未验证 API」、Debug/ASAN 找「Release 遮住的缺陷」、
  既有测试对照找「把设计当缺陷」——三者互补，缺一个都会漏。
