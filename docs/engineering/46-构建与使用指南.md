# 46 · 构建与使用指南

## 环境

CMake 3.20+，启用 C++23 的编译器及平台 SDK。Windows 本轮使用 Visual Studio Build Tools 2022 / MSVC 19.44；第三方代码位于 `third/`。只运行离屏渲染不需要图形 API 或窗口库。

## 构建

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
```

Windows 可显式选择 `-G "Visual Studio 17 2022" -A x64`。Visual Studio 的 `--config` 决定构建类型；Ninja/Makefile 使用 `CMAKE_BUILD_TYPE`。源码位置或生成器改变后应创建新构建目录，不复用旧缓存。

| 选项 | 独立工程默认 | 子工程默认 | 作用 |
| --- | --- | --- | --- |
| `SR_BUILD_EXAMPLES` | ON | OFF | 阶段示例与 demo |
| `SR_BUILD_PRACTICE` | ON | OFF | 自动发现 practice/*.cpp |
| `SR_BUILD_TESTS` | ON | OFF | GoogleTest、像素与安装集成测试 |
| `SR_BUILD_BENCHMARKS` | OFF | OFF | 固定场景 renderer_benchmark，独立于示例开关 |
| `SR_ENABLE_SPDLOG` | ON | ON | 仅启用示例/练习时配置日志依赖 |
| `SR_ENABLE_SANITIZERS` | OFF | OFF | 仅 Debug 启用 ASAN；GCC/Clang 同时启用 UBSAN |
| `SR_UPDATE_GOLDEN` | OFF | OFF | 允许创建缺失的图像基准，不覆盖已有图像 |

只构建库：

```sh
cmake -S . -B build-lib -DSR_BUILD_EXAMPLES=OFF -DSR_BUILD_PRACTICE=OFF -DSR_BUILD_TESTS=OFF
cmake --build build-lib --config Release --parallel
```

## 测试

```sh
# 快速迭代：完整单元测试单进程执行，加像素回归
ctest --test-dir build -C Release -L "fast|regression" --output-on-failure

# 默认 CI 路线：逐单测报告，含两个真实下游工程测试；排除重复的 fast 项
ctest --test-dir build -C Release --parallel 4 -LE fast --output-on-failure

# 安装和源码集成专项
ctest --test-dir build -C Release -L packaging --output-on-failure
```

`packaging` 会编译独立消费者，需要比单测更长的时间。测试产物在 `build/integration/`；图像基准使用编译期注入的绝对路径，测试不要求从源码根目录启动。

像素基准位于 `tests/fixtures/golden/`，缺失默认失败。维护流程见[像素级回归测试](27-像素级回归测试.md)，不能通过自动重建基准掩盖渲染缺陷。

## Sanitizer

```sh
cmake -S . -B build-asan -DSR_ENABLE_SANITIZERS=ON -DCMAKE_BUILD_TYPE=Debug -DSR_BUILD_EXAMPLES=OFF -DSR_BUILD_PRACTICE=OFF
cmake --build build-asan --config Debug --target unit_tests render_regression --parallel
ctest --test-dir build-asan -C Debug -L "fast|regression" --output-on-failure
```

MSVC 运行测试前，需把对应编译器的 `VC/Tools/MSVC/<版本>/bin/Hostx64/x64` 加入当前进程 `Path`，以便找到 ASAN DLL。测试发现推迟至 CTest 启动时，构建本身无需运行测试程序。

Debug 下两项验证 Release 越界哨兵的用例会跳过，因为 Debug 的 assert 会先终止程序；其余用例正常执行。MSVC 不提供 UBSAN，本仓另配置 Ubuntu ASAN+UBSAN CI，远端结果应单独验收。

## 运行示例

从仓库根目录运行，确保 `output/` 存在：

```powershell
.\build\bin\Release\stage10_shadow.exe
.\build\bin\Release\stage10_shadow_live.exe  # Windows 窗口，需手动关闭
```

单配置生成器输出到 `build/bin/`。实时示例不能作为无人值守冒烟测试；离屏示例可用于 CI。

## 集成与安装

源码集成：

```cmake
add_subdirectory(path/to/softrender softrender-build)
target_link_libraries(myapp PRIVATE SoftRenderer::softrenderer)
```

独立安装：

```sh
cmake --install build --config Release --prefix ./build/install
cmake -S <消费工程> -B <消费构建目录> -DCMAKE_PREFIX_PATH=<安装前缀绝对路径>
```

消费工程：

```cmake
find_package(SoftRenderer 1.0 CONFIG REQUIRED)
target_link_libraries(myapp PRIVATE SoftRenderer::softrenderer)
```

不要手工拼装 include 路径或重复定义 `*_IMPLEMENTATION`；公共目标已经提供传递依赖。需要自定义安装布局时，在配置阶段传入相对路径，例如 `-DCMAKE_INSTALL_INCLUDEDIR=include/sr-public`。若把 `CMAKE_INSTALL_LIBDIR` 改成 `custom-lib` 等非标准目录，下游需设置 `-DSoftRenderer_DIR=<前缀>/custom-lib/cmake/SoftRenderer`，仅指定前缀不足以发现任意目录名。细节见[CMake 安装导出](24-CMake工程化-安装导出与版本.md)。

## 工具不可见时

若 CMake 不在 Path，可从 Visual Studio Developer PowerShell 运行，或使用 VS 附带的 `Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe` / `ctest.exe`。当前状态与已验证范围见[项目状态](../project_context.md)。
