# 46 · 构建与使用指南

> 从零开始构建、测试、使用本渲染器的完整指南。

## 一、环境要求

- C++17 编译器（MSVC 2019+、GCC 9+、Clang 10+）
- CMake 3.16+
- 无其他系统依赖（所有第三方库源码在 `third/`）

## 二、构建

```bash
# 配置
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

# 编译全部
cmake --build build --config Release --parallel

# 只编译测试
cmake --build build --config Release --target unit_tests
```

Windows + Visual Studio：
```bash
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

## 三、运行测试

```bash
ctest --test-dir build --build-config Release --output-on-failure
# 或直接
./build/bin/Release/unit_tests
```

## 四、运行示例

```bash
# 离屏渲染（输出 TGA 到 output/）
./build/bin/Release/stage8_offline

# 实时窗口（Windows）
./build/bin/Release/stage8_realtime
```

## 五、作为库使用

### 方式 1：add_subdirectory

```cmake
add_subdirectory(path/to/渲染器)
target_link_libraries(myapp PRIVATE SoftRenderer::softrenderer)
```

### 方式 2：find_package（安装后）

```bash
cmake --install build --prefix /usr/local
```

```cmake
find_package(SoftRenderer REQUIRED)
target_link_libraries(myapp PRIVATE SoftRenderer::softrenderer)
```

### 方式 3：手动 include（不推荐）

> ⚠️ 优先用方式 1 或 2。本方式仅用于无法使用 CMake 目标的环境。
> 下方用 `target_include_directories` 而非 `include_directories`：
> `cpp_project_rules.md`「构建系统规范」明令禁止全局指令，因为它隐式作用于
> **所有**目标且无法从目标定义看出依赖。

```cmake
target_include_directories(myapp PRIVATE
    path/to/softrenderer/src
    path/to/softrenderer/third            # tiny_obj_loader.h
    path/to/softrenderer/third/stb        # stb_image / stb_image_write
    path/to/softrenderer/third/tinygltf   # tiny_gltf.h
    path/to/softrenderer/third/nlohmann   # json.hpp（tinygltf 依赖）
    path/to/softrenderer/third/entt/src   # entt/entt.hpp
)

# 必须编译**三个**实现单元，缺一不可（否则链接报未解析符号）：
target_sources(myapp PRIVATE
    path/to/softrenderer/third/tinygltf/tiny_gltf_impl.cpp   # → stb_image + stb_image_write
    path/to/softrenderer/src/scene/gltf_loader_impl.cpp      # → tinygltf
    path/to/softrenderer/third/tiny_obj_loader_impl.cpp      # → tinyobjloader
)

# MSVC 还需两个定义（否则中文注释报 C4819、core/tga.h 的 std::fopen 报 C4996）
if(MSVC)
    target_compile_options(myapp PRIVATE /utf-8)
    target_compile_definitions(myapp PRIVATE _CRT_SECURE_NO_WARNINGS)
endif()
```

> ⚠️ **实现单元与文件名的对应关系与直觉相反**：`tiny_gltf_impl.cpp` 位于
> `tinygltf/` 目录、名字也叫 `tiny_gltf_impl`，但它**完全不含 tinygltf 的实现**，
> 只提供 stb；tinygltf 的实现在 `src/scene/gltf_loader_impl.cpp`。
> 三个单元各自 `#define` 不同的 `*_IMPLEMENTATION` 宏，**不能在多个 .cpp 里
> 重复定义**（会符号重定义）。完整对照表见 `third/README.md`。

## 六、CMake 选项

| 选项 | 默认 | 说明 |
|---|---|---|
| `SR_ENABLE_SPDLOG` | ON | 启用 spdlog 日志 |
| `CMAKE_BUILD_TYPE` | Release | Debug/Release/RelWithDebInfo |

## 七、中文路径问题

CMake 对含中文的路径可能崩溃。解决方案：
```powershell
# Windows：创建 junction 软链接
New-Item -ItemType Junction -Path D:\softrender -Target "d:\code\.std\渲染器"
cd D:\softrender
cmake -S . -B build ...
```
