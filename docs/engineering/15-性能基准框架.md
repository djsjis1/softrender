# 17 · 性能基准与基线

> 企业级库必须量化性能。项目里有三套工具，用途不同：`benchmarks/support/benchmark.h` 做局部微基准，`renderer_benchmark` 做固定场景整帧基线，`renderer_stress` 做场景级压测与回归对比。

| 工具 | 测什么 | 何时用 |
|---|---|---|
| `sr::Bench`（`benchmarks/support/benchmark.h`） | 单个函数的多次迭代平均 | 验证某个内核改写是否变快 |
| `renderer_benchmark` | 固定场景整帧分布（p50/p95/哈希） | 判断管线级性能是否退化 |
| `renderer_stress` | 116 个登记场景（`SR_SCENARIO()`，以 `--list` 实测为准） | 大范围巡检 + `--baseline` 回归对比 |

聚合平均值不能当作整帧分位数：局部 `Bench` 的数字只说明内核，不说明整帧。

## 一、局部基准（sr::Bench）

```cpp
#include "benchmark.h"  // benchmarks/support/，随 SR_BUILD_BENCHMARKS 目标提供，非公共头

{
    sr::Timer t("rasterize_100_triangles");   // RAII 计时
    for (int i = 0; i < 100; ++i) rasterize(...);
}

sr::benchRun("barycentric_1M", [&]() {        // 多次迭代
    volatile auto bc = barycentric(v0, v1, v2, p);
}, 1000000);

sr::Bench::instance().report();               // 打印汇总
```

输出格式：

```
===== Benchmark Results =====
Name                                         Avg(us)    Min(us)    Max(us)    Iters
rasterize_100_triangles                        45.20      42.10      51.30        1
barycentric_1M                                  0.01       0.01       0.02  1000000
=============================
```

设计要点：`benchRun` 先预热一次排除冷启动；微秒精度用 `high_resolution_clock`；同名多次 record 自动累加；不使用时不产生任何代码。

## 二、整帧基线（renderer_benchmark）

```sh
cmake -S . -B build-bench -DCMAKE_BUILD_TYPE=Release -DSR_BUILD_BENCHMARKS=ON -DSR_BUILD_EXAMPLES=OFF -DSR_BUILD_PRACTICE=OFF -DSR_BUILD_TESTS=OFF
cmake --build build-bench --config Release --target renderer_benchmark --parallel
```

Windows Visual Studio 运行 `build-bench/bin/Release/renderer_benchmark.exe`；单配置生成器运行 `build-bench/bin/renderer_benchmark`。每场景输出一行 JSON，可直接重定向到文件。该目标默认关闭。

固定条件：640×360、1 线程、4096 三角形球体，Flat 与 Phong 两种着色。每场景预热 5 帧，记录 31 帧。
计时采用 `steady_clock`，包含 clear 与 drawMesh，不含资源创建、输出与哈希；Profiler 关闭以避免采样干扰。
p95 使用最近秩法的第 30 个排序样本；同时输出中位数、最小值、最大值与最终 RGBA 的 FNV-1a 64 位哈希。

## 三、2026-10-06 基线快照

环境：AMD Ryzen 7 9700X，Windows x64，MSVC 19.44.35228，Release。原始记录位于 `build/coverage-*-benchmark.jsonl`（已随构建目录清理，重跑即可复现）。

| 实现阶段 | Flat 中位数 / p95 (ms) | Phong 中位数 / p95 (ms) |
| --- | --- | --- |
| 修改前浮点全包含覆盖 | 5.1970 / 7.0480 | 9.2833 / 10.3096 |
| 首版正确整数覆盖 | 6.4824 / 8.1632 | 10.6544 / 12.2736 |
| 最终：整数取整/包围盒 + 背面先剔除 | 4.8947 / 6.6016 | 10.2264 / 11.6715 |

| 场景 | 修改前哈希 | 最终哈希 |
| --- | --- | --- |
| Flat | 316364f8124d6164 | ea9ceba9d9970c1c |
| Phong | 3411697e9f5f19fe | 3411697e9f5f19fe |

Flat 的边缘归属与量化改变了像素，不能把新哈希解释为与旧画面逐字节相同；三个既有像素回归均在原阈值内通过。
最终 Phong 中位数仍高于修改前，因此不能宣称整条管线普遍加速——要判断稳定收益，需控制后台负载并多次交错运行 A/B。

## 四、场景压测与回归对比

```sh
cmake --build build --config Release --target renderer_stress --parallel
build/bin/Release/renderer_stress --quick                       # 快速巡检
build/bin/Release/renderer_stress --json out.json               # 采集基线
build/bin/Release/renderer_stress --baseline out.json           # 与基线对比
```

超基线 1.5 倍且多 5 ms 记为 `[SLOW]`；未指定 `--baseline` 时摘要打印 `regressions=n/a`，不会给出虚假的 0。
压测场景源码在 `benchmarks/stress/`，新增场景用 `SR_SCENARIO()` 登记即可。

## 五、边界与注意

- 覆盖规则（1/256 像素量化、2^20 坐标上限、共享边确定性）见 [31 · 增量式边函数与 SIMD 光栅化](../guide/31-增量式边函数与SIMD光栅化.md) 与 [ADR-003](../adr/ADR-003-raster-coverage.md)。
- 相同端点的共享边确定性不等于自动修复 T 结点，也不能消除不同裁剪算法产生的不一致端点。
- 深度/属性仍按原始浮点几何插值，覆盖偏置不参与属性权重。
- 该基线只测两个固定场景的完整帧，没有拆分顶点/裁剪/片元阶段，也没有比较多线程或 SIMD 对主 Renderer 的收益。
- 绝对时间阈值不能用于跨构建类型断言（Debug+ASAN 下同一算子可能慢 12 倍）；性能回归只在同构建、同机的 baseline 对比里判断。
