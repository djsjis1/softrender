# 58 · 覆盖规则与主渲染性能基线

本轮将像素中心和 MSAA 子样本统一到确定性的 top-left 规则，并修复 MSAA 颜色提交。
整数覆盖解决共享边归属，性能变化需单独测量。设计见 [ADR-003](../adr/ADR-003-raster-coverage.md)。

## 复现

```sh
cmake -S . -B build-bench -DCMAKE_BUILD_TYPE=Release -DSR_BUILD_BENCHMARKS=ON -DSR_BUILD_EXAMPLES=OFF -DSR_BUILD_PRACTICE=OFF -DSR_BUILD_TESTS=OFF
cmake --build build-bench --config Release --target renderer_benchmark --parallel
```

Windows Visual Studio 运行 `build-bench/bin/Release/renderer_benchmark.exe`；单配置生成器运行 `build-bench/bin/renderer_benchmark`。
输出每场景一行 JSON，可直接重定向到文件。该目标默认关闭，不影响已有示例数与消费工程默认配置。

> 本文下面的数字是 2026-10-06 的实测**快照**。更全面的性能/容量数据（`renderer_stress`，当前 105 个场景，含后处理、SSAO、MSAA、2D、IO）用 `--json` 采集，可直接用 `--baseline` 做回归对比。压测场景源码在 `benchmarks/stress/`，新增场景用 `SR_SCENARIO()` 登记即可。

固定条件：640×360、1 线程、4096 三角形球体，Flat 与 Phong 两种着色。每场景预热 5 帧，记录 31 帧。
计时采用 steady_clock，包含 clear 与 drawMesh；不包含资源创建、输出、哈希。Profiler 关闭以避免采样本身干扰。
p95 使用最近秩法的第 30 个排序样本；同时输出中位数、最小值、最大值与最终 RGBA 的 FNV-1a 64 位哈希。

## 2026-10-06 本机记录

环境：AMD Ryzen 7 9700X，Windows x64，MSVC 19.44.35228，Release。
原始记录位于 `build/coverage-*-benchmark.jsonl`。数值是本次运行结果，不代表硬件上限。

| 实现阶段 | Flat 中位数 / p95 (ms) | Phong 中位数 / p95 (ms) |
| --- | --- | --- |
| 修改前浮点全包含覆盖 | 5.1970 / 7.0480 | 9.2833 / 10.3096 |
| 首版正确整数覆盖 | 6.4824 / 8.1632 | 10.6544 / 12.2736 |
| 最终：整数取整/包围盒 + 背面先剔除 | 4.8947 / 6.6016 | 10.2264 / 11.6715 |

量化后的范围已知，初始化改用有界截断和整数除法，避免逐顶点 round/floor/ceil 调用；
先剔除背面后再构造覆盖方程，减少不可见三角形的设置成本。首版新增开销明显降低。
但最终 Phong 中位数仍高于修改前，因此不能宣称整条管线普遍加速；要判断稳定收益，还需控制后台负载并多次交错运行 A/B。

| 场景 | 修改前哈希 | 最终哈希 |
| --- | --- | --- |
| Flat | 316364f8124d6164 | ea9ceba9d9970c1c |
| Phong | 3411697e9f5f19fe | 3411697e9f5f19fe |

Flat 的边缘归属和量化改变了像素，不能把新哈希解释为与旧画面逐字节相同。
三个既有像素回归均在原阈值内通过，未修改基准图；独立覆盖测试检查矩形每个样本恰好属于一个三角形。

## 边界与后续

- 量化步长 1/256 像素，屏幕坐标绝对值上限 2^20；非有限、范围外、量化后退化的三角形不绘制。
- 相同端点的共享边确定性不等于自动修复 T 结点或不同裁剪算法产生的不一致端点。
- 深度/属性仍按原始浮点几何插值，覆盖偏置不参与属性权重。
- 该基线只测两个固定场景的完整帧，没有拆分顶点/裁剪/片元阶段，也没有比较多线程或 SIMD 对主 Renderer 的收益。
- 下一步先扩充有代表性的负载与阶段耗时，再评估 tile、顶点缓存或更宽 SIMD。
