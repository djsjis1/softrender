# 11 · 抗锯齿：从锯齿到平滑

> 斜线边缘的"楼梯"是离散采样的原罪。本篇讲清锯齿的成因，以及 GPU 和我们的渲染器用来消除它的核心手段——**MSAA（多重采样抗锯齿）**。

## 一、锯齿从哪来

光栅化对每个像素做二值判定：中心点在三角形内 → 画，否则 → 不画。当三角形边缘斜穿像素时，相邻像素要么全亮要么全暗，形成阶梯——这就是**走样（aliasing）**。

根本原因：采样率（1 样本/像素）低于信号频率（边缘的高频跳变）。信号处理告诉我们，提高采样率或低通滤波可以消除走样。

## 二、MSAA 的核心思想

**每个像素取 N 个子采样点**（如 4 个），各自独立做"在不在三角形内"的覆盖判定和深度测试。但**片元着色只跑一次**（用像素中心的重心坐标），把结果颜色只写入被覆盖且通过深度测试的样本槽。最后 **resolve**（合成）时把 N 个样本取平均。

效果：边缘像素只有部分样本被覆盖（如 4 个中 2 个），resolve 后得到"半透明"的混合色——视觉上就是平滑过渡。

与 **SSAA**（超采样）的区别：SSAA 对每个子样本都跑完整片元着色器（N 倍开销）；MSAA 着色只跑 1 次，仅多做 N 次廉价的覆盖+深度测试。这是 GPU 硬件的标配方案。

## 三、采样点模式

4x MSAA 常用**旋转网格**模式（避免与水平/垂直边缘对齐导致漏采）：

```
(+3/8, +1/8), (+1/8, +3/8), (-1/8, -3/8), (-3/8, -1/8)
```

代码 `src/core/msaa_framebuffer.h` 的 `kMSAA4Offsets` 正是这组偏移。

## 四、对应代码

| 概念 | 代码 |
|---|---|
| 多样本帧缓冲 | `src/core/msaa_framebuffer.h`：`MSAAFramebuffer<N>` |
| 每样本深度测试 | `testDepth(x, y, sampleIdx, z)` |
| Resolve（平均） | `resolve(dst)` |
| 常量颜色采样管线 | `src/raster/msaa_renderer.h`：`sr::MSAAFlatRenderer<1/4>` |
| 对比示例 | `examples/stage11_msaa.cpp` |

## 五、实现边界与提交顺序

stage9 示例使用 sr::MSAAFlatRenderer，输入已是屏幕坐标与常量颜色，并不执行通用 Shader。
共享 coverage.h 判定样本后，立即在同一个深度通过分支提交该样本颜色；没有额外的像素中心深度竞争。
即使中心在三角形外，被覆盖的子样本仍然着色，背景也不能覆盖已被近处几何占据的样本颜色。

MSAAFramebuffer 的尺寸必须为正，容量溢出抛出 length_error；非法样本编号不读写，非法像素的 coverageCount 返回 0。
单独使用 testDepth/setSample 时，调用方仍需保证颜色仅在深度通过后提交。resolve 平均所有样本，包括未覆盖的背景色。

## 六、动手实验

1. 对比 `sr::MSAAFlatRenderer<1>` 与 `<4>`。8/16 样本需要先定义对应采样模式，不能只改模板参数。
2. 把采样偏移全改成 `{0,0}`（即 4 个样本都在中心），MSAA 退化成无 AA——理解"采样点分布"的重要性。

## 七、小结

- 锯齿 = 采样率不足；MSAA 用多子样本做覆盖+深度，着色只 1 次。
- 旋转网格采样避免轴向偏差。
- Resolve 取平均产生边缘半透明混合。
