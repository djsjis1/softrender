## 一、这个项目是什么

**纯 CPU 手写的软光栅渲染器**：不借助 OpenGL / DirectX / Vulkan，把"给一堆 3D 三角形 + 相机 + 光源，算出屏幕每个像素的颜色"从头实现一遍。这正是显卡内部做的事。

核心设计：

- **可读性优先于性能**：每行代码对应一条图形学原理
- **核心计算与平台隔离**：`include/` 与 `src/` 不引用任何平台代码，`platform/` 是可选显示层
- **第三方库以源码集成**：`third/` 目录，随项目一起编译，无需额外安装

## 二、渲染数学在干什么

渲染的输入是一堆三角形（3D 几何），输出是一张 2D 像素图。这两种东西用的坐标系完全不同——3D 坐标是无界的浮点数，2D 屏幕是整数像素格。

**渲染数学的本质，就是"坐标系跳转"**：

```
模型空间（物体自己的坐标）
   ↓ 模型矩阵 → 平移到世界某个位置
世界空间（全局 3D 坐标）
   ↓ 视图矩阵 → 把世界搬到相机眼前
相机空间（从相机位置看）
   ↓ 投影矩阵 → 计算近大远小
裁剪空间（埋好透视伏笔）
   ↓ 透视除法 ÷w → 真正的近大远小在此发生
NDC（规整立方体 [-1,1]³）
   ↓ 视口变换 → 映射到像素
屏幕像素
```

每跳一次就是一次矩阵乘法，这就是为什么**矩阵**是渲染的"通用语言"；而矩阵里的每个元素都是**向量**算出来的。所以路径是：**向量 → 矩阵 → 变换 → 高级技巧**。

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel

## 九、2D 子系统速查

项目有完整的 2D 渲染子系统（`sr::draw2d`），与 3D 管线**共用同一个 Framebuffer**：

| 模块 | 核心文件 | 职责 |
|------|----------|------|
| 矢量图元 | `render/draw2d/shape2d.h` | 矩形/圆/椭圆/多边形/圆角矩形 |
| 图像合成 | `render/draw2d/blit2d.h` | 缩放/旋转/仿射变换/精灵 |
| 2D 渲染器 | `render/draw2d/renderer2d.h` | 变换栈、Camera2D、scissor、字体 |
| 混合模式 | `core/blend.h` | Opaque/AlphaBlend/Additive/Multiply |

**两条红线**：`Framebuffer` 坐标约定不可修改（y 向上，左下角原点）；`draw2d::plotBlend` 是 2D 唯一像素写入出口。

## 十、怎么读最有效

1. **先跑代码再看文档**：每读一篇，打开对应 `.h`，找到同名函数，看注释里的公式，再在测试里写一行调用验证。
2. **几何直觉优先**：公式不重要，重要的是"它在 3D 空间里到底发生了什么"。
3. **遇到代码立刻测试**：读完一篇就跑对应测试，例如 `.\build\bin\Release\unit_tests.exe --gtest_filter="Vec.*"`。
4. **`examples/` 是参考答案，不是教材**：先看源码、先自己写，实在卡住了再翻。

每篇文档都是四层结构：**直觉 → 公式 → 对应代码 → 动手实验**。
