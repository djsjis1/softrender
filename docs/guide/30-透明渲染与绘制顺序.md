# 30 · 透明渲染：混合公式与绘制顺序

> 不透明物体用深度测试解决遮挡；半透明物体必须用**混合（blending）**——新颜色与已有颜色按 alpha 加权合成。而混合不满足交换律，所以绘制顺序本身决定了画面正确性。本篇把混合公式与渲染队列放在一起讲。

## 一、混合公式

通用形式：`result = src * srcFactor + dst * dstFactor`

| 模式 | srcFactor | dstFactor | 用途 |
|---|---|---|---|
| AlphaBlend | srcA | 1-srcA | 标准半透明（玻璃、水） |
| Additive | 1 | 1 | 发光、粒子、HDR bloom |
| Multiply | dst | 0 | 阴影、暗化 |
| Premultiplied | 1 | 1-srcA | 预乘 alpha（推荐，避免边缘黑边） |

混合**不满足交换律**：A 叠 B ≠ B 叠 A。所以透明物体必须**从远到近**画（画家算法）。这正是 `RenderQueue` 对 `Transparent` 层做远→近排序的原因。

不透明物体先画（写深度），透明物体后画（不写深度，只混合）。

## 二、渲染队列的排序规则

"来一个画一个"在只有不透明物体时勉强能用，但一旦有半透明物体，绘制顺序就决定了画面正确性。渲染队列把所有 DrawCall 收集起来，按规则排序后统一执行。

| 层 | 排序方向 | 原因 |
|---|---|---|
| Background | 任意 | 最先画，通常全屏 |
| Opaque | **近→远** | 利用 Early-Z：近的先写深度，远的被剔除 |
| AlphaTest | 近→远 | 同不透明（镂空后深度正确） |
| Transparent | **远→近** | 画家算法：远的先画，近的混合覆盖 |
| Overlay | 任意 | 最后画（UI） |

同层内按 **materialId** 分组，减少 Shader/纹理切换。

## 三、排序键编码

把 layer(16bit) + materialId(16bit) + distance(32bit) 编码成一个 `uint64_t`，一次整数比较完成排序。透明层的 distance 位取反，实现"远→近"。

## 四、预乘 alpha 的优势

普通 alpha 纹理的边缘纹素通常是 `(0,0,0,0)`（透明黑）。混合时 `src*srcA + dst*(1-srcA)` 中 `src*0 = 0`，但双线性插值会在边缘混入黑色 → 黑边。

预乘 alpha 在导入时就把 RGB 乘上 A 存好，混合公式变成 `src*1 + dst*(1-srcA)`，插值时黑色纹素的 RGB 已经是 0，不会产生额外暗化。

## 五、对应代码

| 概念 | 代码 |
|---|---|
| 混合模式枚举 | `include/softrenderer/core/blend.h`：`BlendMode` |
| 像素混合函数 | `blendPixels(src, dst, mode)` |
| 渲染层枚举 | `include/softrenderer/render/pipeline/render_queue.h`：`RenderLayer` |
| DrawItem | 带 layer/materialId/distance/meshIndex |
| 排序 | `RenderQueue::sort(cameraPos, positions)` |
| 统计 | `countOpaque()` / `countTransparent()` |

## 六、动手实验

1. 构造 3 个透明物体在不同距离，故意按错误顺序加入队列，排序后确认远的先画。
2. 混合不透明+透明物体，确认不透明全部排在透明前面。
3. 把 `AlphaBlend` 换成 `Premultiplied`，对比边缘质量。

## 七、小结

- 混合不满足交换律 → 透明必须远→近。
- 队列按层排序，同层按 materialId 分组减少状态切换。
- 排序键打包成一次 `uint64_t` 比较，透明层距离取反。
- 预乘 alpha 消除半透明边缘黑边。
