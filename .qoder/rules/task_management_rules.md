# 任务管理规范

## 核心原则

AI Agent 在执行多步骤任务时容易"迷失方向"。

任务必须有书面记录，状态必须可追踪。

禁止凭记忆管理复杂任务。

> S / M 级小变更（按 `ai_workflow_rules.md` 的变更分级判定）无需创建 TASK 文件；触及「大型需求拆分规则」任一阈值的任务必须建档。

每个任务文件命名：`TASK-<三位编号>-<简短描述>.md`

```markdown

- 创建日期：2025-06-01
- 状态：进行中
- 涉及模块：timeline, commands, ui

## 目标

实现时间轴编辑的 Undo/Redo 功能，支持移动、删除、属性修改三类操作的撤销。

## 当前状态

已完成命令模式的基础架构（Command 抽象基类、CommandQueue），
正在实现 MotionCommand 的 execute/undo 方法。
```

# 任务状态流转

```
待开始 → 进行中 → 代码审查 → 已完成

任意阶段可 → 阻塞（需注明阻塞原因）
任意阶段可 → 取消（需注明取消原因）
```

## AI 自动状态更新

AI 在以下时机必须更新任务状态：

| 时机 | 操作 |
|------|------|
| Step 1（需求分析）后 | 达到「大型需求拆分规则」阈值的任务创建 TASK 文件，状态「待开始」（S/M 级小变更免建档） |
| Step 5（编码实现）开始时 | 状态改为「进行中」 |
| 每个子任务完成时 | 勾选进度清单 |
| Step 7（最终确认）后 | 状态改为「代码审查」或「已完成」 |
| 遇到阻塞时 | 状态改为「阻塞」，记录原因 |
| 任务完成后 | 移动到 `DONE/` 目录，更新 README.md 索引 |

# AI 对话中的任务管理

多步骤任务或 L 级变更时，对话开始时 AI 必须：

1. 读取 `docs/tasks/README.md` 了解所有任务
2. 读取 `docs/tasks/ACTIVE.md` 了解当前任务
3. 如果 ACTIVE 指向无文件或无当前任务，主动询问

每次对话结束时，AI 必须：

1. 更新当前任务文件的状态和进度
2. 若创建了新任务，更新 README.md 索引
3. 若有任务完成，移动文件到 DONE/

# 大型需求拆分规则

单个需求超过以下阈值必须拆分为子任务：

* 涉及模块 ≥ 3 个
* 预计代码变更 ≥ 500 行
* 预计实现时间 ≥ 2 天

拆分方式：

* 每个子任务创建独立 TASK 文件
* 父任务在「进度清单」中引用子任务编号
* 子任务可独立完成，但需在父任务中汇总

---

# 禁止行为

禁止：

* 不创建任务文件就开始大规模修改代码
* 任务完成后不归档（文件长期留在待开始状态）
* 多个不相关的修改共用一个 TASK（应创建独立任务）
* 修改任务目标但不更新任务文件
* 删除历史任务文件（应归档到 DONE/）
