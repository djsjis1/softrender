# AI 工作流规范

## 核心原则

AI 禁止直接输出大量代码。必须先分析、设计、规划，再实现。

## 变更分级（决定流程深度）

| 级别 | 判定标准 | 流程要求 |
|------|----------|----------|
| S | 单文件、改动 < 30 行、不涉及公共接口与架构 | 简述意图 → 直接编码 → 简化自检 |
| M | 单模块、改动 < 300 行 | Step 1、2、5、6、7（无需双方案比较） |
| L | 跨模块 / 公共接口 / 架构级 / 引入新依赖 | 完整七步，Step 3 双方案比较，按需触发 ADR |

* 定级就高不就低，拿不准时升一级；用户明确要求走完整流程时按 L 执行。
* 对应级别的流程内，不得跳过任意步骤。
* **S 级无需填写任何步骤模板**——在对话中直接说明「改什么、为什么改」，编码完成后做简化自检即可。

---

# Step 0：项目上下文确认（开工前）

开始任务前先确认项目上下文，禁止在未了解上下文的情况下直接编码：

1. 读取 `docs/tasks/ACTIVE.md` 与 `docs/architecture.md`（若存在）
2. 确认当前任务目标与最近变更（changelog / 分支）
3. 上下文不足时先向用户确认

---

# Step 1：需求分析

理解用户真实意图，而非字面需求。

输出格式：

```markdown
## 需求分析

1. 用户意图：[一句话描述核心目标]
2. 功能边界：[做什么 / 不做什么]
3. 非功能需求：[性能、安全、兼容性等]
4. 隐含约束：[现有架构限制、技术栈限制等]
```

若需求不明确，必须先向用户确认，禁止猜测后直接编码。

---

# Step 2：影响范围分析

分析本次变更将触及的所有模块和文件。

输出格式：

```markdown
## 影响范围

### 新增文件
- path/to/new_file.h
- path/to/new_file.cpp

### 修改文件
- path/to/existing_file.h — [修改原因]
- path/to/existing_file.cpp — [修改原因]

### 删除文件
- path/to/deprecated_file.h — [删除原因]

### 不修改但受影响
- path/to/caller.cpp — [间接影响说明]
```

---

# Step 3：设计方案

至少提供两个方案并给出推荐。

输出格式：

```markdown
## 设计方案

### 方案 A：[名称]
- 思路：[简述]
- 优点：[列出]
- 缺点：[列出]

### 方案 B：[名称]
- 思路：[简述]
- 优点：[列出]
- 缺点：[列出]

### 推荐：方案 X
- 选择原因：[说明]
```

涉及架构级变更必须画出 Mermaid 时序图或类图。

若涉及设计模式选择、第三方库引入、协议选择等重大决策，必须按 `architecture_decision_record.md` 创建 ADR。

---

# Step 4：文档更新计划

编码前先确定需要同步更新的文档（按 `documentation_rules.md` 判定）。

输出格式：

```markdown
## 文档更新计划

### 必须更新
- docs/architecture.md — [原因]
- docs/api.md — [原因]

### 无需更新
- docs/database.md — [不涉及数据库变更]
```

必须在编码前列出，编码后再次确认。

---

# Step 5：编码实现

遵循 `engineering_rules.md` 和 `cpp_project_rules.md` 的编码规范，按 `testing_rules.md` 编写测试，按 `task_management_rules.md` 更新任务进度。

---

# Step 6：自检

编码完成后逐项自检（本节为规则体系**唯一自检清单**，各文件不再另设检查清单）：

✓ 架构与编码：符合 `engineering_rules.md` 和语言规则（C++ 见 `cpp_project_rules.md`）
✓ 命名达意、注释解释「为什么」、无死代码
✓ 错误路径完整处理，无静默失败；关键路径有日志
✓ 资源管理（RAII / 智能指针）、无魔数
✓ 新增逻辑有对应测试；不可自动化路径已留钩子并自测通过

发现问题必须立即修复，不得标记后忽略。

---

# Step 7：最终确认

全流程最终输出格式（适用于 L 级；S / M 级用三行摘要即可：变更文件 / 验证结果 / 文档结论）：

```markdown
## 完成确认

### 代码变更
- [文件列表]

### 文档同步
- [已更新文档列表]
- [不需要更新及原因]

### 任务状态
- 更新 `docs/tasks/TASK-XXX.md` 进度

### 建议 Commit（自动执行）
- 格式见 `git_rules.md`，AI 自动 git add + commit
- 按变更级别自动决定是否创建分支

### 变更日志
- [日期] [版本] [简述变更内容] [影响范围]
```
